Шаблон AI-провайдера — подключение к языковой модели, которое администратор готовит для пользователей портала.
В шаблоне задаются URL, метод, заголовки и модели, а пользователь при подключении провайдера из шаблона выбирает модель и, в зависимости от шаблона, вводит свой токен.

AI-провайдер нужен пользователю для работы с [платформенным агентом](platform-agent/) и с внешними агентами, которым разрешён прокси моделей DDP.

## Источник токена

Шаблон работает в одном из режимов, который задаёт поле «Источник токена»:

| Режим | Как работает |
| --- | --- |
| «Личный токен каждого пользователя» | Пользователь подключает провайдера из шаблона в профиле и вводит свой токен |
| «Один общий токен на всех» | Токен задаётся в шаблоне. Провайдер появляется у каждого пользователя, которому разрешён шаблон, без подключения. Такой провайдер нельзя удалить или изменить в профиле |

Токен хранится в зашифрованном виде и подставляется в заголовки запроса вместо `{{ .token }}`.

## Создание шаблона

Чтобы создать шаблон:

1. Перейдите в раздел «AI» → «AI-агенты» → «Шаблоны AI-провайдеров». Раздел доступен с разрешением `edit:ai-provider-templates`.
1. Нажмите «Создать».
1. Заполните поля шаблона, как описано в разделе [«Параметры шаблона»](#параметры-шаблона).
1. Нажмите «Сохранить».

## Параметры шаблона

Форма шаблона содержит поля:

| Поле | Обязательность | Описание |
| --- | --- | --- |
| «Название» | Да | Название шаблона, которое видят пользователи при подключении провайдера |
| «Описание» | Нет | Краткое описание для пользователей при подключении |
| «Модель по умолчанию» | Да | Модель, если пользователь не выбрал другую |
| «Доступные модели» | Нет | Модели, которые может выбрать пользователь. Пустой список — любая модель |
| «Включён» | — | Отключённый шаблон нельзя использовать для новых подключений |
| «URL» | Да | URL API провайдера, например `https://api.openai.com/v1/chat/completions` |
| «Метод» | Да | HTTP-метод запроса к провайдеру |
| «Источник токена» | Да | Режим работы шаблона. Подробнее — в разделе [«Источник токена»](#источник-токена) |
| «Токен» | Для общего токена | Токен, которым авторизуются все пользователи шаблона. При редактировании пустое значение сохраняет текущий токен |
| «Заголовки» | Нет | HTTP-заголовки запроса. Токен подставляется вместо `{{ .token }}`, например `Authorization: Bearer {{ .token }}` |
| «Поле ответа» | Нет | Путь к тексту ответа модели в JSON-ответе провайдера, например `choices.0.message.content` |
| «Шаблон тела запроса» | Нет | JSON-шаблон тела запроса с переменными `{{.prompt}}` и `{{.model}}` |

Чтобы шаблон работал с агентами, укажите API, совместимый с OpenAI Chat Completions: URL оканчивается на `/v1` или `/v1/chat/completions`.

Если переключить шаблон с общего токена на личный, общий токен удаляется.
Шаблон, из которого подключены провайдеры пользователей, удалить нельзя.

### Пример шаблона для OpenAI

Пример шаблона с общим токеном для API OpenAI:

| Поле | Значение |
| --- | --- |
| «Название» | `OpenAI` |
| «Модель по умолчанию» | `gpt-4o` |
| «URL» | `https://api.openai.com/v1/chat/completions` |
| «Метод» | `POST` |
| «Источник токена» | «Один общий токен на всех» |
| «Токен» | API-ключ OpenAI |
| «Заголовки» | `Authorization: Bearer {{ .token }}` |

## Доступ к шаблону

Шаблон с личным токеном может подключить любой пользователь портала.

Шаблон с общим токеном доступен супер-администратору и пользователям, которым выдана роль с разрешением `use:ai-provider-templates` на этот шаблон.
Чтобы выдать доступ, в меню карточки шаблона выберите «Настроить доступ» и создайте привязку роли для пользователей или команд.

Отключённые шаблоны видят только пользователи с разрешением `read:ai-provider-templates` или `edit:ai-provider-templates`.
Остальным пользователям заголовки шаблона показываются только со значениями-подстановками.

## Провайдер из шаблона у пользователя

У провайдера, подключённого из шаблона, пользователь меняет только название, модель в пределах списка «Доступные модели» и токен.
URL, метод, заголовки и остальные параметры подключения портал подставляет из шаблона, поэтому изменения шаблона сразу применяются ко всем подключённым провайдерам.

В профиле такой провайдер отмечен как «из шаблона», а провайдер из шаблона с общим токеном — как «общий токен».
Как пользователь подключает провайдера, описано в разделе [«Подключение AI-провайдера»](../../user/ai-assistant/#подключение-ai-провайдера).

## AI-провайдеры сервис-аккаунтов

Сервис-аккаунт не может войти в профиль, поэтому его AI-провайдерами управляет администратор с разрешением `edit:users`.
AI-провайдер сервис-аккаунта нужен, например, когда процесс с элементом «AI-агент» запускается от имени сервис-аккаунта.

Чтобы настроить AI-провайдера сервис-аккаунта:

1. Перейдите в раздел «Администрирование» → «Пользователи».
1. В строке сервис-аккаунта нажмите кнопку с подсказкой «Управление AI-провайдером этого сервис-аккаунта».
1. Подключите провайдера из шаблона или задайте свою конфигурацию, как в профиле пользователя.
