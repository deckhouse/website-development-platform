AI-агент получает задачу на естественном языке, обращается к языковой модели и вызывает инструменты для подготовки ответа или выполнения работы.
Deckhouse Development Portal (DDP) подключает агентов по протоколу A2A (Agent2Agent) версии 1.0.

Агенты из каталога используются в [AI-ассистенте](../../user/ai-assistant/), виджете [«AI-чат»](../widgets/ai/chat/) и элементе процесса [«AI-агент»](../processes/overview/#ai-агент).
Для работы с файлами проекта доступен также отдельный [агент рабочего пространства](../../user/workspaces/).

## Виды агентов

Подключение агента задаётся его карточкой Agent Card, которую агент публикует как JSON, обычно по адресу `/.well-known/agent-card.json`:

| Вид | Подключение |
| --- | --- |
| [Платформенный агент](platform-agent/) | Разворачивается с порталом и подключается автоматически, идентификатор `ddp-agent` |
| [Внешний агент](external-agents/) | Подключается администратором по URL карточки и API-ключу |
| [Агент из источника](agent-sources/) | Создаётся источником по сущности каталога |

Портал отправляет агенту сообщение по A2A и получает ответ. Сам агент выполняется вне backend портала.

## Языковая модель агента

Агент использует собственные доступы к модели или прокси моделей DDP.
При работе через прокси портал использует AI-провайдера пользователя, запустившего задачу, и расходует его квоту.

В каталоге источник модели отображается как «Модель DDP» или «Модель агента».

Платформенный агент всегда использует прокси.
Для внешнего агента включите «Разрешить прокси моделей DDP» в настройках подключения, если модель должен предоставлять портал.

Прокси работает с API, совместимым с OpenAI Chat Completions.
К URL провайдера добавляется `/chat/completions`, если суффикса ещё нет.
Требуются модель и токен; поля провайдера «Шаблон тела запроса» и «Поле ответа» для агентского запроса не используются.

Прокси не поддерживает `stream: true` и подставляет модель AI-провайдера вместо модели из запроса агента.

## Инструменты агента

На вкладке «Инструменты и навыки» задайте «MCP-коллекции».
Агент получает инструменты включённых коллекций, которыми может пользоваться запускающий пользователь через свои коллекции.
Проверка прав на объекты портала выполняется отдельно при каждом вызове.

Без коллекций агент работает без MCP-инструментов.
Это правило одинаково для платформенного агента, внешних агентов, чата, виджетов и процессов.
Состав коллекции может включать инструменты портала, подключённых MCP-серверов и пользовательские HTTP-инструменты.

Например, чтобы агент читал каталог, включите `ddp_get_resources` и `ddp_get_resource_entities` в коллекцию, подключите её к агенту и предоставьте пользователю право использовать её.
Для запуска процессов добавьте `get_processes`, `run_process` и `get_process_instance`.

Пошаговая настройка — [в руководстве по MCP-коллекциям](../../user/mcp-management/#mcp-коллекции).

## Навыки агента

На той же вкладке назначьте [навыки](skills/) с конкретной версией или привязкой «Последняя».
При запуске агент получает их названия и описания, полный текст читает через `get_skill` при необходимости.
Этот инструмент должен быть доступен через коллекции агента и пользователя.

Для инструкций и материалов в GitLab настройте [источник навыков](skill-sources/).

## Доступ к агентам

Использование регулируется глобальным `use:ai-agents` или объектным `use:ai-agent` для конкретного подключения.
Право действует для чата, виджета и шага процесса.
Оно не предоставляет доступ к данным каталога и не выдаёт инструменты MCP.

Просмотр и изменение регулируются отдельными правами:

| Объект | Глобальные разрешения | Разрешения конкретного объекта |
| --- | --- | --- |
| Агент | `read:ai-agents`, `edit:ai-agents` | `read:ai-agent`, `edit:ai-agent`, `use:ai-agent` |
| Источник агентов | `read:ai-agents`, `edit:ai-agents` | `read:ai-agent-source`, `edit:ai-agent-source` |
| Шаблон AI-провайдера | `read:ai-provider-templates`, `edit:ai-provider-templates`, `use:ai-provider-templates` | `read:ai-provider-template`, `edit:ai-provider-template`, `use:ai-provider-template` |

Владение и участие в команде-владельце предоставляют права при включённом `owner-is-admin`.
Доступ можно выдать другим пользователям и командам через «Настроить доступ».
Супер-администратор имеет доступ ко всем подключениям.

История своих запусков требует `read:ai-agent-runs`, остановка — `cancel:ai-agent-runs`.
Для раздела «AI» требуется `view:ai-page`; само по себе это разрешение не выдаёт доступ к его объектам.

## Токен запуска и ограничения

Для разрешённых обращений к MCP и прокси моделей портал передаёт короткоживущий токен запуска.
После завершения или остановки запуска токен отзывается.

Для запусков A2A-агентов действуют ограничения:

| Ограничение | Значение |
| --- | --- |
| Максимальная длительность запуска | 70 минут |
| Максимальный срок токена | 75 минут |
| Вызовы MCP | 120 в минуту на запуск |
| Запросы к прокси моделей | 60 в минуту на запуск |
| Размер запроса к прокси | 1 МиБ |
| Размер ответа модели через прокси | 4 МиБ |
| Тайм-аут запроса к модели | 90 секунд |

Ошибки и результаты проверяйте [в истории запусков](runs/), сводные показатели — [в статистике AI](../../user/ai-statistics/).
