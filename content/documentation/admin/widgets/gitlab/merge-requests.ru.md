Виджет показывает merge request (MR) проекта GitLab и позволяет создавать, сливать и закрывать их.

## Конфигурация

| Название   | Обязательность | Описание                                                                   | Значение по умолчанию |
| ---------- | -------------- | -------------------------------------------------------------------------- | --------------------- |
| URL        | Да             | URL GitLab API. Используется для получения данных из GitLab                | —                     |
| ID проекта | Да             | ID проекта, из которого будут загружаться данные в виджет. Пример: `12345` | —                     |

## Фильтрация

Над таблицей расположены фильтры по состоянию MR с числом MR в каждом состоянии: «Все», «Открытые», «Черновики», «Слитые», «Закрытые».

По умолчанию выбран фильтр «Открытые»: он показывает открытые MR без черновиков. Открытые черновики отображаются в фильтре «Черновики».

Список «в» с вариантом «Все ветки» фильтрует MR по целевой ветке. Справа отображается число найденных MR из общего числа.

## Таблица

В таблице отображаются колонки:

- ID — номер MR со ссылкой на GitLab;
- «Статус» — состояние MR;
- «Название» — название MR, тег «Черновик» и значок конфликта с подсказкой «Конфликты с целевой веткой»;
- «Автор» и «Ревьюеры»;
- «Ветка» — ветка-источник, в подсказке — ветка-источник и целевая ветка;
- «Обновлён» — время последнего изменения;
- меню «Действия».

Нажмите на строку, чтобы раскрыть сведения о MR: даты создания и изменения, ревьюеры, число изменённых файлов с числом добавленных и удалённых строк, статус пайплайна и ссылка «Открыть в GitLab».

## Действия с MR

Действия с MR доступны в раскрытой строке и в меню «Действия»:

- «Слить» — слияние MR после подтверждения;
- «Закрыть» — закрытие MR;
- «Отметить как черновик» и «Отметить как готово» — изменение признака черновика;
- «Изменения» — список изменённых файлов в раскрытой строке или построчное сравнение файлов в отдельном окне из меню «Действия»;
- «Открыть в GitLab» — переход к MR в GitLab.

Если MR нельзя слить, рядом с кнопками отображается причина:

- «Слить можно только открытый MR»;
- «Черновик нельзя слить»;
- «Конфликты с целевой веткой»;
- «Пайплайн не зелёный» — последний пайплайн MR завершился не успешно.

{{< alert level="info" >}}
Для выполнения действий с MR требуются соответствующие права доступа в репозитории GitLab.
{{< /alert >}}

### Создание MR

Кнопка «Создать MR» в заголовке виджета открывает окно создания MR. Заполните поля «Ветка-источник», «Целевая ветка», «Название» и, при необходимости, «Описание» и нажмите «Создать».

Ветка-источник и целевая ветка должны различаться. Поле «Название» обязательное.

## Размещение на главной

Виджет выводится на вкладке «MRs» карточки микросервиса на главной, если он выбран в слоте `microservice_merge_requests_widget` [правил маппинга](../../home/mapping/#слоты-виджетов).
В этом случае в поле «ID проекта» укажите `{{ .context.repository.id }}`: карточка микросервиса передаёт виджету ID проекта своего репозитория.
