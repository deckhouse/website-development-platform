Ресурс `ddp_runtime` содержит `config_json`, описывающий основную среду рабочего пространства. Deckhouse Development Portal (DDP) использует этот контракт для проверки Pod, подключения IDE и подготовки входов исполнителя. Встроенный модуль формирует JSON из своих параметров.

## Контракт основной среды

JSON использует имена полей в camelCase и отклоняет неизвестные поля. Корневые параметры:

| Поле | Тип JSON | Назначение |
| --- | --- | --- |
| `contractVersion` | `string` | Версия контракта, `"1"` |
| `podSelector` | Объект строк | Непустой селектор Pod; включает workspace и generation |
| `container` | `string` | Имя основного контейнера по правилам DNS label |
| `controlPort` | Целое | Порт управления от `1` до `65535` |
| `idePort` | Целое | Порт IDE от `1` до `65535`, отличный от `controlPort` |
| `persistentDirectory` | `string` | Абсолютная постоянная директория |
| `attemptDirectory` | `string` | Абсолютная временная директория попытки |
| `image` | `string` | Образ исполнителя с `@sha256:` и `64` строчными шестнадцатеричными символами |
| `profile` | Объект | Профиль запуска; требуется для исполнения среды DDP |
| `files` | Массив объектов | Файлы, доставляемые в проект; может отсутствовать |

Селектор связывает под с принятой операцией:

```json
{
  "ddp.deckhouse.io/workspace": "<WORKSPACE_UUID>",
  "ddp.deckhouse.io/generation": "<GENERATION>"
}
```

Значения в HCL берутся из `data.ddp_workspace`. `<GENERATION>` — строковое представление поколения; это не произвольный пользовательский параметр. DDP дополнительно получает фактический UID Pod перед выдачей доступа.

Директории нормализованы, не равны `/`, не содержат переводы строк и обратную косую черту. Постоянная и временная директории не совпадают и не вложены друг в друга. Встроенный модуль добавляет к временной основе `/run/attempt` суффикс `generation-<GENERATION>`.

## Параметры профиля

`profile` определяет пути, OpenCode, ограничения и IDE:

| Поле | Тип | Значение во встроенной основе | Назначение |
| --- | --- | --- | --- |
| `version` | Целое | `1` | Версия профиля |
| `workDirectory` | Строка | `/workspace/code` | Репозиторий и рабочая директория команд |
| `stateDirectory` | Строка | `/workspace/state` | Постоянные данные OpenCode и подготовки |
| `runtimeDirectory` | Строка | `/run/credentials` | Временные реквизиты текущего поколения |
| `engineBinary` | Строка | `/usr/local/bin/ddp-opencode` | Исполняемый файл OpenCode |
| `toolPath` | Строка | `/workspace/state/user-home/bin:/usr/local/bin:/usr/bin:/bin` | PATH исполнителя и инструментов |
| `gitHistoryDepth` | Целое | `50` | Глубина первоначального clone, от `1` до `10000` |
| `engine` | Объект | Описан ниже | Параметры OpenCode и его запросов |
| `limits` | Объект | Описан ниже | Ограничения событий, ответов и запуска |
| `ide` | Объект | Описан ниже | Постоянные и временные директории IDE |

`workDirectory` и `stateDirectory` находятся внутри `persistentDirectory` и не пересекаются. `runtimeDirectory` находится вне постоянной директории и не пересекается с директориями попытки. `engineBinary` находится вне постоянной директории. `toolPath` состоит из нормализованных абсолютных путей, разделённых двоеточием.

Для установки SDK добавляйте исполняемые файлы или ссылки в `/workspace/state/user-home/bin`. Этот каталог входит в PATH среды и IDE. Сам SDK можно хранить рядом в постоянном пользовательском каталоге.

## OpenCode

`engine` задаёт лимиты контекста, ответов и ожидания. AI-провайдер и модель выбираются при создании рабочего пространства и привязываются DDP отдельно от этого профиля.

Поля `engine`:

| Поле | Тип | Значение во встроенной основе | Назначение |
| --- | --- | --- | --- |
| `contextTokens` | Целое | `128000` | Размер контекста модели |
| `outputTokens` | Целое | `8192` | Максимальный размер ответа модели |
| `requestTimeoutMs` | Целое | `90000` | Общий тайм-аут запроса к модели |
| `headerTimeoutMs` | Целое | `30000` | Ожидание заголовков |
| `chunkTimeoutMs` | Целое | `30000` | Ожидание следующей части потокового ответа |
| `bashTimeoutMs` | Целое | `60000` | Тайм-аут shell-инструмента OpenCode |
| `port` | Целое | `14096` | Локальный порт OpenCode |
| `username` | Строка | `ddp` | Пользователь аутентификации локального API |
| `templateConfig` | Объект | Отсутствует | Разрешённые дополнения конфигурации |

Все числовые лимиты положительные. `outputTokens` не превышает `contextTokens`. Порт от `1` до `65535` отличается от портов управления и IDE. `username` не пустой, без двоеточия, перевода строки и окружающих пробелов. Пароль генерирует DDP для текущего поколения.

## Дополнения конфигурации OpenCode

`engine.templateConfig` позволяет подключить инструкции, команды и дополнительные инструменты. DDP проверяет допустимые ключи и затем добавляет собственные настройки модели, MCP и временного доступа.

Поддерживаются поля:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `instructions` | Массив строк | Файлы инструкций OpenCode |
| `plugin` | Массив строк | Явно заданные плагины |
| `command` | Объект | Именованные команды |
| `mcp` | Объект | Дополнительные MCP-серверы |
| `lsp` | Объект или `false` | Language Server Protocol |
| `formatter` | Объект или `false` | Форматирование кода |

Размер JSON не превышает `64 KiB`. Имена MCP соответствуют `^[a-z][a-z0-9_-]{0,63}$`. Имя `ddp` и имена с префиксом `ddp_` зарезервированы. Команда не задаёт `model`, `agent` или `subtask`. Строковые подстановки OpenCode `{env:...}` и `{file:...}` отклоняются.

Добавление инструкции в существующий `engine`:

```hcl
templateConfig = {
  instructions = ["AGENTS.md"]
  command = {
    review = {
      template    = "Проверь изменения в рабочей директории и опиши найденные ошибки."
      description = "Проверить изменения"
    }
  }
  lsp       = false
  formatter = false
}
```

Это дополнение к `module.workspace.runtime_profile.engine`. Сохраните остальные обязательные поля `engine`. Файл `AGENTS.md` должен существовать в проекте; его можно доставить [через шаблон](examples/#инструкции-opencode).

Проектная конфигурация не подменяет модель, основной DDP MCP и управление заданиями. Плагины и инструменты выполняются внутри среды с её доступом к файлам и сети; включайте их как часть доверенного шаблона.

## Ограничения исполнителя

`limits` задаёт ограничения журналов, запросов и ожидания готовности:

| Поле | Значение во встроенной основе | Назначение |
| --- | --- | --- |
| `maxFiles` | `2048` | Максимальное число обрабатываемых файлов или действий |
| `maxEventBytes` | `1048576` | Объём журнала событий в байтах |
| `maxEventStreamBytes` | `67108864` | Объём потока событий в байтах |
| `maxEventFrameBytes` | `65536` | Максимальный размер отдельного события |
| `maxResponseBytes` | `8388608` | Размер обрабатываемого ответа |
| `startupTimeoutMs` | `60000` | Ожидание запуска среды |
| `healthRequestTimeoutMs` | `2000` | Тайм-аут проверки готовности |
| `pollIntervalMs` | `1000` | Интервал проверки событий OpenCode |
| `shutdownGraceMs` | `10000` | Ожидание завершения при остановке |

Все значения положительные. `maxEventFrameBytes` не превышает `maxEventBytes` и `maxEventStreamBytes`. `healthRequestTimeoutMs` не превышает `startupTimeoutMs`. Тайм-ауты в миллисекундах должны помещаться в представление длительности исполнителя.

Политика платформы и профиль должны быть согласованы. Лимит журнала подготовки не превышает `maxEventBytes`, а лимит отдельного доставляемого файла не превышает `maxResponseBytes`. Ограничения служебных Jobs и запросов Kubernetes задаются отдельно [в настройках установки](configuration/).

## IDE

`ide` определяет сохраняемые данные code-server и временную конфигурацию:

| Поле | Значение во встроенной основе | Назначение |
| --- | --- | --- |
| `homeDirectory` | `/workspace/state/user-home` | Домашняя директория пользователя |
| `userDataDirectory` | `/workspace/ide/data` | Настройки и данные IDE |
| `extensionsDirectory` | `/workspace/ide/extensions` | Расширения |
| `configDirectory` | `/run/ide-config` | Временная конфигурация |

`homeDirectory` равна `<stateDirectory>/user-home`. Данные и расширения находятся внутри постоянной директории, не пересекаются между собой и с checkout. Конфигурация IDE находится вне постоянных данных, реквизитов runtime и директории попытки.

Если профиль объявляет IDE, DDP создаёт приватный вход `/ide-input/ide.json`. Сам путь входит в контракт поставки. Токены и пароль текущего поколения не сохраняются в PVC вместе с настройками IDE.

## Доставка файлов

`files` содержит желаемые файлы относительно `workDirectory`. Встроенный модуль передаёт его из `module.workspace.files`.

Элемент массива:

```hcl
{
  path       = "config/local.env"
  policy     = "create_if_missing"
  content    = "APP_MODE=development\n"
  executable = false
}
```

Поля файла:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `path` | Строка | Нормализованный относительный путь |
| `policy` | Строка | `create_if_missing` или `managed` |
| `content` | Строка | Содержимое UTF-8 |
| `executable` | Логическое | Разрешение выполнения файла |

Путь не превышает `1024` байта. Он не содержит `..`, `.git`, `.ddp`, пустые компоненты, обратную косую черту, двоеточие или управляющие символы. Пути уникальны; файл и его дочерний путь не могут одновременно быть файлами.

Контракт допускает до `10000` файлов, `1 MiB` на файл и `64 MiB` содержимого суммарно. К ним дополнительно применяются политика платформы и ограничения профиля.

`create_if_missing` создаёт отсутствующий файл и сохраняет имеющееся содержимое. `managed` учитывает последнюю применённую версию шаблона и изменения пользователя. Конфликты разрешаются явно при создании или обновлении. Перед записью DDP повторно проверяет содержимое; изменение файла после планирования требует нового плана.
