Deckhouse Development Portal (DDP) проверяет глобальные разрешения и владельца рабочего пространства. Разрешение на администрирование шаблонов не открывает личные пространства других пользователей.

## Пользовательские разрешения

Для создания и работы с личным пространством выдайте разрешения по требуемым действиям:

| Действие | Разрешение |
| --- | --- |
| Читать шаблоны и опубликованные версии | `read:workspace-templates` |
| Использовать шаблон при создании | `use:workspace-templates` |
| Читать доступные внешние подключения | `read:external-services` |
| Читать свои пространства, историю и квоты | `read:workspaces` |
| Создавать и восстанавливать пространство | `create:workspaces` |
| Открывать IDE, отправлять задание и восстанавливать соединение | `read:workspaces` и `create:workspaces` |
| Останавливать пространство | `cancel:workspaces` |
| Планировать и применять обновление | `update:workspaces` |
| Удалять пространство | `delete:workspaces` |

Создание дополнительно требует `use:workspace-templates` и `read:external-services`. Для работы из AI-чата нужны разрешения выбранного ассистента и `run:ai-agents`.

Повтор неудачной операции проверяет разрешение исходного действия: создания, остановки, обновления или удаления. Доступность кнопки также зависит от состояния, принятой операции и блокировок.

## Администрирование

Административные действия требуют `view:admin-page` и соответствующего разрешения:

| Действие | Разрешение |
| --- | --- |
| Читать список шаблонов | `read:workspace-templates` |
| Создать шаблон | `create:workspace-templates` |
| Редактировать метаданные, файлы, черновики и архив | `edit:workspace-templates` |
| Опубликовать версию и читать результат подготовки | `publish:workspace-templates` |
| Активировать версию | `activate:workspace-templates` |
| Читать «Настройки подключения» | `read:workspace-connection-settings` |
| Сохранять «Настройки подключения» | `edit:workspace-connection-settings` и `read:external-services` |
| Читать «Лимиты и квоты» | `read:workspace-policy` |
| Сохранять «Лимиты и квоты» | `edit:workspace-policy` |

Для запуска теста черновика дополнительно нужны `read:workspace-templates`, `edit:workspace-templates`, `use:workspace-templates`, `create:workspaces` и `read:external-services`.

## Владение

Список пространств и подробности ограничены владельцем. Знание UUID не даёт доступ к чужим файлам, заданиям, планам, истории операций, lifecycle или IDE.

Шаблон с `credentials_mode = "fixed_user"` использует реквизиты указанного пользователя для Kubernetes. Владельцем пространства остаётся создавший его пользователь DDP.

## Доступ к Kubernetes

Разрешения DDP управляют действиями пользователя в портале, а Kubernetes Role и ClusterRole определяют права выбранных внешних подключений. Подготовьте права отдельно для служебного и целевого кластеров.

Необходимые операции зависят от используемого шаблона:

| Область | Требуемый доступ |
| --- | --- |
| Служебный неймспейс | Создание, чтение, наблюдение, изменение и удаление Jobs; чтение связанных Pods и управление служебными объектами операции |
| Целевой неймспейс | Чтение, создание, изменение и удаление объектов, объявленных шаблоном |
| Подключение к среде | Чтение Pod, доступ `pods/portforward` для управления и IDE |
| Проверка и подготовка файлов | Доступ `pods/exec` к принятому служебному контейнеру |
| Хранение | Чтение PVC и соответствующего PersistentVolume |
| Подтверждение завершения процессов | Чтение Node и Lease узла в `kube-node-lease` |
| Подтверждение отключения тома | Чтение списка VolumeAttachment |
| Отдельный неймспейс | Создание и удаление Namespace, объявленного шаблоном |

Чтение Node, PersistentVolume и VolumeAttachment относится к объектам уровня кластера; Lease узла находится вне неймспейса пространства. Прав одного неймспейса для полного подтверждения завершения записи недостаточно.

Доступ для наблюдения не означает право изменять узлы или тома. Если проверки завершения и отключения недоступны, DDP оставляет блокировку последующей записи вместо выдачи второго разрешения.

В служебных Jobs и стандартном Pod `automountServiceAccountToken = false`. Значение `service_account` задаёт ServiceAccount пода, но не выбирает владельца реквизитов Kubernetes API. Брокер DDP разрешает целевые реквизиты по `credentials_mode`.

Поддерживаемые Kubernetes-профили перечислены [в составе модуля](module/#редактирование-инфраструктуры). Широкая Kubernetes-роль не разрешает пакету обходить ограничения брокера DDP.

## GitLab и модель

GitLab-подключение должно соответствовать HTTPS-origin репозитория. У владельца должны быть реквизиты для получения commit и clone; для push предоставьте право записи в проект.

Токен не включается в URL репозитория и не сохраняется в `.git/config`. Исполнитель получает ограниченный Git credential helper на время поколения. Автор коммитов задаётся из email владельца.

AI-провайдер должен поддерживать используемый DDP формат OpenAI Chat Completions и вызовы инструментов. Его выбирают отдельно от ассистента чата. Для модели и инструментов задания DDP выдаёт ограниченный токен, привязанный к run, поколению, Pod и сроку.
