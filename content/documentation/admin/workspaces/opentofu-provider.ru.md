Провайдер `deckhouse/ddp` версии `0.1.0` связывает OpenTofu-пакет с контекстом рабочего пространства Deckhouse Development Portal (DDP). Версия контракта — `1`. Провайдер описывает логические декларации; Pod, PVC и другие Kubernetes-объекты создаёт провайдер `hashicorp/kubernetes`.

## Подключение

Провайдеры входят в образ исполнителя DDP и проверяются по manifest и контрольным суммам. Пакет фиксирует совместимые версии:

```hcl
terraform {
  required_version = "= 1.13.0"
  required_providers {
    ddp = {
      source  = "deckhouse/ddp"
      version = "= 0.1.0"
    }
    kubernetes = {
      source  = "hashicorp/kubernetes"
      version = "= 2.38.0"
    }
  }
}

provider "ddp" {}
provider "kubernetes" {}
```

Полный адрес провайдера DDP — `registry.opentofu.org/deckhouse/ddp`. В DDP подготовка выполняется с провайдерами из образа, без загрузки изменяемых зависимостей из сети. При первой подготовке создаётся `.terraform.lock.hcl`; при повторной подготовке сохранённый файл блокировки проверяется.

Блок `provider "ddp"` не принимает параметры. Исполнитель передаёт принятый контекст через приватный файл `DDP_WORKSPACE_CONTEXT_FILE`. Проверка схемы и синтаксиса допускается без принятой операции; чтение источников данных и применение деклараций требуют контекста DDP. Автор шаблона не задаёт этот контекст в переменных или в `.tfvars`.

Приватные файлы контекста и источника запуска принадлежат UID исполнителя, имеют размер до `1 MiB` и права без доступа группы и остальных пользователей. Символические и жёсткие ссылки, JSON с неизвестными полями и дополнительные данные после JSON отклоняются.

## Состав провайдера

Провайдер предоставляет следующие элементы:

| Вид | Имя | Назначение |
| --- | --- | --- |
| Источник данных | `ddp_workspace` | Идентичность, поколение и желаемое состояние среды |
| Источник данных | `ddp_parameter` | Декларация пользовательского параметра и его принятое значение |
| Ресурс | `ddp_template` | Подключение, неймспейс, реквизиты и хранение данных |
| Ресурс | `ddp_runtime` | JSON-контракт основной среды |
| Ресурс | `ddp_runtime_source` | Приватные входные данные для запуска текущего поколения |
| Ресурс | `ddp_script` | Скрипт подготовки или каждого запуска |
| Ресурс | `ddp_resource_policy` | Классификация объекта инфраструктуры |

Логические ресурсы `ddp_template`, `ddp_runtime`, `ddp_script` и `ddp_resource_policy` имеют вычисляемое строковое поле `contract_version`. OpenTofu также сохраняет их `id`; он не является UUID шаблона или Kubernetes-объекта. Создание этих деклараций не выполняет shell-команды. Скрипты исполняет среда после принятия операции DDP.

## Контекст рабочего пространства

`data "ddp_workspace"` не принимает входных аргументов. Значения определяет принятая сервером операция:

```hcl
data "ddp_workspace" "current" {}
```

Доступны вычисляемые поля:

| Поле | Тип | Значение |
| --- | --- | --- |
| `uuid` | `string` | UUID рабочего пространства |
| `owner_uuid` | `string` | UUID владельца |
| `version_uuid` | `string` | UUID версии пакета, используемой операцией |
| `target_uuid` | `string` | UUID закреплённой цели |
| `namespace` | `string` | Неймспейс рабочего пространства |
| `suffix` | `string` | Постоянный суффикс имён, связанный с пространством |
| `generation` | `number` | Положительное целое, поколение операции |
| `transition` | `string` | `create`, `start`, `stop`, `update` или `delete` |
| `start_count` | `number` | `1` для `create/start`, `0` для `stop/update/delete` |
| `inspection_count` | `number` | `1` для принятой DDP проверки постоянных файлов, иначе `0` |
| `preparation_count` | `number` | `1` для принятой DDP подготовки при обновлении, иначе `0` |

`start_count` показывает желаемое наличие работающей среды, а не число запусков. Привязывайте к нему временные Pod и Secrets. Постоянный PVC создавайте независимо от `start_count`, с именем на основе `suffix`.

`inspection_count` и `preparation_count` задаёт DDP для операций `update` при `start_count = 0`. Их нельзя использовать как пользовательские переключатели запуска служебных сред.

## Пользовательский параметр

`ddp_parameter` описывает поле формы создания или обновления. Имена уникальны во всём пакете, включая локальные модули.

Параметр количества потоков:

```hcl
data "ddp_parameter" "workers" {
  name         = "workers"
  label        = "Количество потоков"
  description  = "Число потоков приложения"
  type         = "number"
  required     = true
  mutable      = true
  default_json = jsonencode(2)
  minimum      = "1"
  maximum      = "8"
}

locals {
  workers = jsondecode(data.ddp_parameter.workers.value_json)
}
```

Аргументы и результат:

| Поле | Тип OpenTofu | Обязательное | Назначение |
| --- | --- | --- | --- |
| `name` | `string` | Да | Имя по шаблону `^[a-z][a-z0-9_]{0,63}$` |
| `label` | `string` | Да | Непустое название поля, до `256` байт |
| `description` | `string` | Нет | Подсказка, до `4096` байт |
| `type` | `string` | Да | `string`, `number`, `bool` или `list(string)` |
| `required` | `bool` | Да | Требует значение, когда нет значения по умолчанию |
| `mutable` | `bool` | Да | Разрешает явное обновление после создания |
| `default_json` | `string` | Нет | JSON значения по умолчанию |
| `options_json` | `list(string)` | Нет | До `100` уникальных допустимых JSON-значений |
| `minimum` | `string` | Нет | Нижняя включительная граница типа `number` |
| `maximum` | `string` | Нет | Верхняя включительная граница типа `number` |
| `pattern` | `string` | Нет | Регулярное выражение Go для типа `string` |
| `value_json` | `string` | Вычисляется | Принятое значение в JSON |

Используйте `jsonencode` при задании значения и `jsondecode` при его чтении. Для строки JSON должен содержать JSON-строку: `jsonencode("small")`. Для числа используйте `jsonencode(2)`, для логического значения — `jsonencode(false)`. Список строк кодируется как `jsonencode(["api", "worker"])`.

Границы заданы строками, чтобы отличать отсутствие границы от `"0"`. Они должны быть конечными числами; `minimum` не превышает `maximum`. Значения `options_json` и `default_json` проходят проверку типа, границ и регулярного выражения. Если требуется совпадение всей строки, задайте в `pattern` якоря `^` и `$`.

Необязательный параметр без значения возвращает `value_json = "null"`. Заданный `null` не является допустимым значением параметра. `false`, `0`, пустая строка и пустой список сохраняются как значения своих типов. Параметры отображаются пользователю; токены и пароли передавайте через механизмы реквизитов DDP.

## Декларация шаблона

`ddp_template` объявляется один раз в корневом модуле. Она определяет разрешённое целевое подключение и политику хранения:

```hcl
resource "ddp_template" "main" {
  name               = "Рабочее пространство команды"
  description        = "Среда с постоянными данными"
  allowed_services   = [var.kubernetes_service_uuid]
  default_service    = var.kubernetes_service_uuid
  namespace_mode     = "existing"
  allowed_namespaces = [var.namespace]
  credentials_mode   = "owner"
  retention_days     = 0
}
```

Аргументы декларации:

| Поле | Тип | Обязательное | Правило |
| --- | --- | --- | --- |
| `name` | `string` | Да | Непустое название, до `256` байт |
| `description` | `string` | Нет | До `4096` байт |
| `allowed_services` | `list(string)` | Да | От `1` до `100` уникальных ненулевых UUID внешних сервисов |
| `default_service` | `string` | Да | UUID из `allowed_services`; используется формой запуска |
| `namespace_mode` | `string` | Да | `existing` или `per_workspace` |
| `allowed_namespaces` | `list(string)` | Для `existing` | В режиме `existing` непустой список; для формы DDP укажите одно значение |
| `credentials_mode` | `string` | Да | `owner` или `fixed_user` |
| `credential_user_uuid` | `string` | Для `fixed_user` | Ненулевой UUID пользователя; при `owner` поле отсутствует |
| `retention_days` | `number` | Да | Целое от `0` до `36500`; `0` означает хранение до удаления |

Имена неймспейсов соответствуют DNS label: от `1` до `63` символов, строчные буквы, цифры и дефисы; дефис не бывает первым или последним. В режиме `per_workspace` список `allowed_namespaces` пустой или отсутствует. Создание Namespace в OpenTofu-пакете показано [в примере](examples/#отдельный-неймспейс).

Чтобы использовать фиксированного пользователя, замените режим и добавьте UUID:

```hcl
credentials_mode     = "fixed_user"
credential_user_uuid = "<CREDENTIAL_USER_UUID>"
```

Замените `<CREDENTIAL_USER_UUID>` UUID пользователя DDP с нужными реквизитами целевого внешнего сервиса. Это дополнение внутри `ddp_template`. Режим не меняет владельца пространства и не даёт указанному пользователю доступ к IDE владельца.

## Основная среда

`ddp_runtime` объявляется ровно один раз в корневом или локальном модуле, без `count` и `for_each`. Его обязательное строковое поле `config_json` содержит JSON-контракт среды.

Контракт связывает среду с UUID и поколением:

```hcl
resource "ddp_runtime" "main" {
  config_json = jsonencode({
    contractVersion = "1"
    podSelector = {
      "ddp.deckhouse.io/workspace"  = data.ddp_workspace.current.uuid
      "ddp.deckhouse.io/generation" = tostring(data.ddp_workspace.current.generation)
    }
    container           = "runtime"
    controlPort         = var.control_port
    idePort             = var.ide_port
    persistentDirectory = var.persistent_directory
    attemptDirectory    = var.attempt_directory
    image               = var.runtime_image
    profile             = var.runtime_profile
    files               = var.files
  })
}
```

Это пример внутри локального модуля с соответствующими переменными. При использовании встроенного модуля изменяйте его входы, сохраняя единственную имеющуюся декларацию `ddp_runtime`. Полная схема JSON, профиля и файлов приведена [в спецификации среды](runtime-profile/).

## Приватные данные запуска

`ddp_runtime_source` связывает запускаемый Pod с приватными материалами текущей операции. Встроенный модуль уже содержит эту декларацию:

```hcl
resource "ddp_runtime_source" "inputs" {
  count      = data.ddp_workspace.current.start_count
  generation = data.ddp_workspace.current.generation
}
```

Поля ресурса:

| Поле | Тип | Режим | Значение |
| --- | --- | --- | --- |
| `generation` | `number` | Обязательное, смена требует замены | Поколение из принятого контекста |
| `config_json` | `string` | Вычисляемое, `sensitive` | Приватный JSON источника материалов |
| `contract_version` | `string` | Вычисляемое | `"1"` |

Во время планирования `config_json` неизвестен. При применении провайдер читает приватный файл `DDP_WORKSPACE_RUNTIME_SOURCE_FILE` и проверяет workspace, generation, срок доступа и `start_count = 1`. Смена поколения требует свежего источника; сохранённый план не должен закреплять токен предыдущего запуска.

DDP формирует JSON источника; автор пакета не задаёт токен, URL или пути через ресурс. При `count` разрешена привязка к `start_count`; `for_each` не используется.

Поля приватного JSON:

| Поле | Тип | Проверка |
| --- | --- | --- |
| `version` | Целое | `1` |
| `workspaceUuid` | Строка | Ненулевой UUID принятого пространства |
| `generation` | Целое | Положительное, совпадает с контекстом и аргументом ресурса |
| `planBuildUuid` | Строка | Ненулевой UUID плана операции |
| `endpoint` | Строка | HTTPS-эндпоинт материалов конкретных workspace и plan build |
| `grant` | Строка | Временное разрешение, `64` строчных шестнадцатеричных символа |
| `deadlineAt` | Строка даты | Будущий срок действия |
| `requestTimeoutMs` | Целое | Положительное, не больше `pollIntervalMs` |
| `pollIntervalMs` | Целое | Не больше `300000` |
| `maxResponseBytes` | Целое | От `1` байта до `8 MiB + 64 KiB` |
| `jobPath` | Строка | Нормализованный абсолютный путь с именем `job.json` |
| `bootstrapPath` | Строка | Нормализованный абсолютный путь с именем `bootstrap.json` |
| `idePath` | Строка, необязательное | Нормализованный абсолютный путь с именем `ide.json` |

Директории приватных входов раздельные и не находятся непосредственно в корне файловой системы. Endpoint не содержит реквизиты пользователя, query, fragment или кодированный альтернативный путь. Его путь соответствует `/api/v2/workspace-runtime-material/<WORKSPACE_UUID>/<PLAN_BUILD_UUID>`.

Метка `sensitive` скрывает значение в обычном выводе OpenTofu, но оно может находиться в state. Состояние DDP хранится зашифрованным; raw state и планы не предназначены для пользовательских журналов.

## Скрипт среды

`ddp_script` задаёт shell-скрипт для исполнителя рабочего пространства:

```hcl
resource "ddp_script" "prepare_tools" {
  name            = "prepare_tools"
  phase           = "create"
  content         = "mkdir -p \"$HOME/bin\""
  timeout_seconds = 30
  required        = true
  dependencies    = []
}
```

Аргументы скрипта:

| Поле | Тип | Обязательное | Значение |
| --- | --- | --- | --- |
| `name` | `string` | Да | Уникальное имя по шаблону `^[a-z][a-z0-9_]{0,63}$` |
| `phase` | `string` | Да | `create` или `start` |
| `content` | `string` | Да | Непустой shell-код, до `1 MiB` и лимита файла платформы |
| `dependencies` | `list(string)` | Нет | Имена скриптов, которые выполняются раньше |
| `timeout_seconds` | `number` | Да | Положительное целое, не выше лимита скрипта платформы |
| `required` | `bool` | Да | Сбой блокирует готовность, если `true` |

Исполнение происходит через `/bin/sh -eu -c` в директории проекта. Окружение содержит `PATH`, `HOME`, `LANG=C`, `LC_ALL=C`, `TMPDIR`, `DDP_WORKSPACE_UUID` и `DDP_WORKSPACE_GENERATION`. `HOME` соответствует `<stateDirectory>/user-home`. Скрипт выполняется с пользователем контейнера, у встроенной основы — UID `10000`.

Используйте `dependencies` для порядка выполнения скриптов. `depends_on` OpenTofu управляет порядком деклараций инфраструктуры и не заменяет зависимости исполнителя. Имена зависимостей должны существовать; повторы, ссылка на себя и циклы отклоняются. Скрипт `create` не зависит от скрипта `start`.

Успешный `create` сохраняет отметку выполнения и не повторяется при обычном восстановлении. `start` выполняется при каждом явном запуске. Добавленный или изменённый `create` при обновлении показывается в плане подготовки и требует принятия операции. После сбоя между действием скрипта и сохранением отметки возможен повтор; делайте действия идемпотентными.

Если shell-текст содержит буквальные `${...}` или `%{...}`, экранируйте их в HCL как `$${...}` и `%%{...}`.

## Политика инфраструктуры

`ddp_resource_policy` связывает адрес OpenTofu с классом хранения:

```hcl
resource "ddp_resource_policy" "data" {
  address = "kubernetes_persistent_volume_claim_v1.data"
  class   = "protected"
}
```

Аргументы политики:

| Поле | Тип | Обязательное | Значение |
| --- | --- | --- | --- |
| `address` | `string` | Да | Адрес ресурса OpenTofu, до `1024` байт, без перевода строки |
| `class` | `string` | Да | `ephemeral`, `retained` или `protected` |

Классы различаются назначением:

| Класс | Использование |
| --- | --- |
| `ephemeral` | Временные Pod и Secrets, удаляемые при остановке |
| `retained` | Объекты, которые шаблон сохраняет при остановке |
| `protected` | Объекты с данными; удаление и замена блокируются вне подтверждённого удаления пространства |

Класс дополняет конфигурацию OpenTofu. Для сохранения PVC сам ресурс должен существовать при `start_count = 0`. Одна декларация политики не изменяет `count` и не создаёт инфраструктуру.

В локальном модуле можно указывать адрес относительно этого модуля. DDP добавляет область модуля; явный адрес с `module.` остаётся полным. Политика без индекса применяется к экземплярам `count` или `for_each` соответствующего адреса. При обновлении более строгая существующая политика сохраняет приоритет: `protected`, затем `retained`, затем `ephemeral`.

Защита OpenTofu-плана не анализирует произвольный shell-код на удаление файлов. Используйте [доставку управляемых файлов](examples/#управляемый-файл) и проверяйте дополнительные команды шаблона.

## Подготовка деклараций

DDP извлекает форму без выполнения `apply`, provisioners, скриптов и запросов к внешним источникам данных. Декларации `ddp_parameter` и `ddp_template` должны вычисляться статически.

Допускаются литералы, статические `var` и `local`, переданные входы локальных модулей и функции `jsonencode`, `jsondecode`, `tolist`, `toset`. Выражения деклараций с `for`, splat, внешними функциями и данными, известными только после применения, отклоняются. Обычные выражения Kubernetes-ресурсов вычисляет OpenTofu при планировании.

Модули включаются файлами в пакет и вызываются через локальный `source`, например `"./modules/workspace"`. Проверка отклоняет внешние Git/registry-модули и файлы `.tf.json`. Лимиты статической обработки и пакета приведены [в ограничениях](troubleshooting/#ограничения).
