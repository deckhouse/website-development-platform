Главная страница — это витрина каталога: она показывает системы, микросервисы, окружения и ресурсы платформы в виде готовых разделов, не требуя от пользователя знания структуры каталога.

{{< alert level="warning" >}}
Главная страница — экспериментальная функциональность. Состав разделов, структура правил маппинга и API могут измениться в следующих выпусках без сохранения обратной совместимости.
{{< /alert >}}

## Как это работает

Главная страница не хранит собственных данных. Она читает сущности каталога и показывает их в разделах, опираясь на [правила маппинга](../mapping-sets/) — они сообщают платформе, какой ресурс каталога играет роль системы, какой микросервиса, какая связь соединяет систему с её сервисами и какое свойство хранит домен окружения.

Пока правила не заданы, разделы главной страницы остаются пустыми. Быстрее всего задать их [мастером первоначальной настройки](../setup/).

## Включение и отключение

После установки или обновления платформы раздел «Главная» выключен. Пока он выключен, обращение к нему перенаправляет пользователя в «Каталог».

Видимость главной страницы переключается в разделе «Администрирование» → «Правила маппинга» и требует разрешения `update:home-mapping-sets`. Переключатель управляет только отображением раздела в веб-интерфейсе: данные каталога он не меняет.

{{< alert level="warning" >}}
Прежняя главная страница — страница дашбордов — удалена. Размещать произвольные виджеты в разделе «Главная» больше нельзя: он либо показывает витрину каталога, либо выключен.
{{< /alert >}}

## Разделы

Разделы сгруппированы по темам. Наполнены данными следующие:

| Группа | Раздел | Что показывает |
|--------|--------|----------------|
| Архитектура | «Системы» | Дерево систем по доменам, зависимости и интеграции системы |
| Архитектура | «Развертывание систем» | Схема развёртывания: микросервисы, окружения, общие ресурсы и связи между ними |
| Архитектура | «Диаграммы» | Диаграммы зависимостей, состава и развёртывания с выгрузкой в файл |
| Архитектура | «Интеграции» | Интеграции между системами |
| Разработка | «Микросервисы» | Список микросервисов, их репозитории, пайплайны и merge requests |
| Разработка | «Создать микросервис» | Мастер создания микросервиса из [шаблона](../../templates/) |
| Разработка | «Окружения» | Окружения, их домены и размещённые в них развёртывания |
| Разработка | «Как работает платформа» | Краткие руководства по основным сценариям |
| Организация | «Команды» | Карта команд, их состав, системы и микросервисы |
| Организация | «Заказ ресурсов» | Запуск процессов заказа общих ресурсов и история заказов |
| Организация | «Потребление ресурсов» | Потребление CPU и памяти по развёртываниям |
| Организация | «Кластеры и сети» | Кластеры каталога |

Остальные разделы меню помечены значком **TBD** — они зарезервированы под будущие выпуски и данных не содержат.

## Действия из разделов

Часть разделов не только показывает данные, но и запускает процессы каталога: заказ общего ресурса, создание и удаление окружения, развёртывание и удаление микросервиса. Какой именно процесс запускается, определяют группы процессов в [правилах маппинга](../mapping-sets/#группы-процессов).

Запущенный процесс отображается на странице сразу: строка помечается как выполняющаяся, а созданный объект показывается предварительной строкой до тех пор, пока не появится в каталоге после синхронизации.

## Правка домена окружения

В разделе «Окружения» домен окружения можно изменить прямо из карточки: нажмите значок правки рядом с доменом, введите значение и сохраните. Значение записывается в свойство сущности, определённое ролью `environment_domain` в правилах маппинга.

Право на изменение проверяется на бэкенде при сохранении. Если у вас нет разрешения на изменение сущностей, платформа вернёт ошибку.
