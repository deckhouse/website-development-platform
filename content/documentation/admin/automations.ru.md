Автоматизации — механизм реагирования Deckhouse Development Portal (DDP) на изменения спецификации сущностей.

Каждая автоматизация может подписываться на обновления сущностей какого-либо ресурса по определённым правилам.
При возникновении события обновления автоматизация запускает выполнение действия, процесса или синхронизации источника данных.

Автоматизация может запускать выполнение как для сущности, которая вызвала триггер, так и для связанных с ней сущностей в соответствии с настройками.

## Интерфейс настройки автоматизации

Форма создания и редактирования автоматизации разделена на логические секции.

### Триггеры

Секция для настройки условий, при которых автоматизация будет запускаться.
Каждая автоматизация может содержать произвольное количество триггеров.

При настройке каждого триггера указывается «Ресурс» — ресурс, события с сущностями которого будут являться триггером для запуска автоматизации.
Также указывается «Условие» в формате [Go template](https://developer.hashicorp.com/nomad/docs/reference/go-template-syntax).
Оно описывает, изменение какого параметра считается триггером для запуска автоматизации и какое значение должен принять изменённый параметр.

Например, с условием `{{ ne .entity.properties.id 0 }}` автоматизация запускается, если значение параметра `id` изменилось и стало не равным нулю.
С условием `{{ eq .entity.properties.status "Failed" }}` автоматизация запускается, если значение параметра `status` изменилось на `Failed` с любого другого.

### Выполнение

Секция для настройки того, что будет выполняться при срабатывании триггера автоматизации.

В поле «Тип выполнения» выбирается тип объекта, который будет выполняться: действие, процесс или синхронизация источника данных.
В поле «Объект выполнения» выбирается конкретный объект (действие, процесс или источник данных).

Процесс запускается только для сущностей ресурсов, к которым он привязан в поле «Ресурс» [процесса](../processes/overview/#основная-информация).
Поэтому процесс автоматизации должен быть привязан ко всем ресурсам, для сущностей которых автоматизация его запускает: к ресурсам триггеров — если выполнение запускается для сущности, вызвавшей триггер, или по расписанию; к ресурсу на другом конце каждой выбранной связи — если включён запуск для связанных ресурсов.

Если выполнение запускается для сущности, вызвавшей триггер, или по расписанию, в списке «Объект выполнения» процессы, не привязанные к ресурсам триггеров, неактивны с подписью «не привязан к ресурсам триггеров»; привязку к связанным ресурсам портал проверяет при сохранении.
Автоматизация с процессом, не привязанным к нужным ресурсам, не сохраняется.
Портал отвечает ошибкой `422` с текстом «Процесс запускается только для сущностей своих ресурсов: привяжите его к ресурсам, для сущностей которых автоматизация его запускает (ресурсы триггеров или связанные ресурсы), или выберите другой процесс».

Для действий и процессов доступна дополнительная настройка «Запускать выполнение для связанных ресурсов».
При её включении выполнение автоматически запускается для всех сущностей, имеющих соответствующую связь с изменённой сущностью.
При этом выполнение не запускается для сущности, вызвавшей событие.

### Синхронизация

Секция для настройки периодической синхронизации — автоматического запуска автоматизации по расписанию.

Параметр «Периодическая синхронизация» включает и выключает периодическую синхронизацию.
В параметре «Периодичность запуска» задаётся cron-выражение для настройки частоты запуска автоматизации, например `0 0 * * *` для ежедневного запуска в полночь.

## Триггеры

Механизм работы триггеров автоматизаций основан на событиях (events), которые генерируются при каждом создании, изменении либо удалении любой сущности любого ресурса.

Автоматизации:

1. Прослушивают события указанных в конфигурации триггеров ресурсов.
1. Проверяют, изменилось ли значение параметра, указанного в условиях триггера.
1. При изменении сравнивают текущее значение параметра с условием.
1. При соответствии условию запускают выполнение.

{{< alert level="warning" >}}
Новые автоматизации обрабатывают только события, которые произошли после их создания.
События, произошедшие до создания автоматизации, не будут обработаны.
{{< /alert >}}
