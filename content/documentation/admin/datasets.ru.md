Наборы данных — это предварительно настроенные конфигурации, предназначенные для быстрого развёртывания готовых интеграций с внешними системами и настройки необходимых компонентов DDP (портала).

Каждый набор данных содержит:

- дашборды для визуализации данных;
- виджеты для отображения информации;
- источники данных для синхронизации;
- внешние сервисы для подключения к API;
- типы учётных данных для аутентификации;
- роли и права доступа;
- другие необходимые компоненты портала.

## Управление наборами данных

### Просмотр доступных наборов

В разделе «Администрирование» → «Наборы данных» отображается список всех доступных наборов данных. Каждая карточка содержит:

- «Название» — название набора данных.
- «Краткое описание» — общее описание функциональности.
- Кнопка «Описание» — открывает подробную информацию о наборе данных, включая:
  - подробное описание с полной информацией о компонентах;
  - список объектов, которые будут созданы при применении.
- Кнопка «Применить» — запускает процесс установки набора данных.
- Кнопка «Удалить» — удаляет ранее применённый набор данных.

### Применение набора данных

1. Нажмите кнопку «Применить» на карточке нужного набора данных.
1. Если набор данных требует настройки параметров, откроется форма конфигурации.
1. Заполните необходимые параметры и нажмите «Применить».
1. Если параметры не требуются, появится окно подтверждения.
1. После успешного применения все компоненты набора данных будут созданы в системе.

Набор данных, который зависит от другого набора, применяется только после него: иначе применение завершается ошибкой «Ошибка записи набора данных». Если не заполнен обязательный параметр, отображается ошибка «Заполните обязательные параметры набора данных».

### Удаление набора данных

1. Нажмите кнопку «Удалить» на карточке применённого набора данных.
1. Подтвердите удаление в диалоговом окне.
1. Все компоненты набора данных будут удалены из системы.

### Настройка после применения

После применения некоторых наборов данных может потребоваться дополнительная настройка:

1. Перейдите в «Профиль» → «Учётные данные».
1. Заполните необходимые учётные данные (токены, пароли и т. д.).
1. Сохраните изменения.

### Первоначальная настройка

Кнопка «Первоначальная настройка» открывает мастер, который применяет наборы данных «Каноничной архитектуры» для главной одним запуском: модель каталога, правила маппинга, подключения к Kubernetes, Vault и GitLab, источники данных, процессы и виджеты.
Мастер и наборы данных, которые он применяет, описаны в разделе [«Первоначальная настройка»](../home/setup/).

Переключатель «Показывать баннер первоначальной настройки» возвращает на главную баннер «Платформа готова к настройке», скрытый кнопкой «Скрыть».

## Доступные наборы данных

### GitLab

Набор данных предназначен для подключения к API GitLab.

Создаваемые объекты:

- внешний сервис «GitLab»;
- тип учётных данных «GitLab токен» — personal access token для доступа к API GitLab;
- тип учётных данных «GitLab username» — имя пользователя GitLab.

Параметры настройки:

| Название     | Описание                                               | Значение по умолчанию |
|--------------|--------------------------------------------------------|-----------------------|
| «URL GitLab» | Базовый URL GitLab, например `https://gitlab.example.com`. Обязательный параметр | — |

После применения заполните в профиле пользователя учётные данные «GitLab токен» и «GitLab username».

Группы, репозитории и виджеты GitLab для главной создают наборы данных «GitLab: группы», «GitLab: активность репозиториев» и «GitLab: виджеты». Они описаны в разделе [«Первоначальная настройка»](../home/setup/#наборы-данных-мастера).

### Kubernetes

Набор данных предназначен для подключения к API Kubernetes.

Создаваемые объекты:

- внешний сервис «Kubernetes»;
- тип учётных данных «Kubernetes токен» — токен сервисного аккаунта для доступа к API Kubernetes.

Параметры настройки:

| Название             | Описание                                                                  | Значение по умолчанию |
|----------------------|---------------------------------------------------------------------------|-----------------------|
| «URL Kubernetes API» | Базовый URL API-сервера Kubernetes, например `https://api.cluster.example.com`. Обязательный параметр | — |

После применения заполните в профиле пользователя учётные данные «Kubernetes токен».

### Vault

Набор данных предназначен для подключения к API HashiCorp Vault.

Создаваемые объекты:

- внешний сервис «Vault»;
- тип учётных данных «Vault токен» — токен для запросов к API.

Настройка:

Набор данных настраивает подключение к API Vault через внешний сервис с авторизацией по заголовку `X-Vault-Token`. Подробнее о формате авторизации — в разделе [«Внешние сервисы»](../external-services/#vault).

{{< alert level="info" >}}
После применения укажите в профиле суперадминистратора токен Vault в учётных данных «Vault токен».
{{< /alert >}}

Параметры настройки:

| Название    | Описание                        | Значение по умолчанию         |
|-------------|---------------------------------|-------------------------------|
| «URL Vault» | Базовый URL API HashiCorp Vault, например `https://vault.example.com`. Обязательный параметр | —   |

Применение:

1. Примените набор данных Vault.
1. Укажите URL вашего сервера Vault.
1. Перейдите в профиль суперадминистратора.
1. Заполните учётные данные «Vault токен».
1. Подключите внешний сервис «Vault» к действиям, виджетам или источникам данных, которые обращаются к API Vault.

После этого запросы через внешний сервис будут использовать токен из учётных данных пользователя. Например, внешний сервис можно подключить к виджету [«Секреты Vault»](../widgets/generic/vault/) для просмотра секретов в KV v2.

### Deckhouse managed PostgreSQL

Набор данных для развёртывания managed PostgreSQL в Deckhouse Platform.

Набор данных подготавливает ресурс, действия и процессы для управления жизненным циклом managed PostgreSQL: создание инстанса в кластере через внешний сервис Kubernetes и сохранение реквизитов подключения в Vault или Stronghold.

Настройка:

Перед применением настройте внешние сервисы [Kubernetes](../external-services/#kubernetes) и [Vault](../external-services/#vault) (или Stronghold).

{{< alert level="info" >}}
Подробное описание компонентов набора данных доступно по кнопке «Описание» на карточке в разделе «Наборы данных».
{{< /alert >}}

Параметры настройки:

| Название | Описание | Значение по умолчанию |
|----------|----------|-----------------------|
| «Внешний сервис Kubernetes» | Kubernetes кластер, в котором будет разворачиваться managed PostgreSQL. Обязательный параметр | — |
| «Внешний сервис Vault или Stronghold» | Внешний сервис для записи реквизитов подключения в KV v2. Обязательный параметр | — |
| «Префикс пути Vault» | Префикс пути KV v2 для сохранения реквизитов (с `/data/`) | `services/data/` |
| «Создать ресурс каталога» | Создать собственный родительский ресурс набора. Отключите, если процессы привязываются к каноничным общим ресурсам | Включено |
| «Создать действия» | Создать действия создания и удаления managed-сервиса | Включено |
| «Создать процессы» | Создать процессы создания и удаления managed-сервиса | Включено |
| «Создать источник данных» | Собирать инстансы managed-сервиса из кластера в каталог: статус, окружение, класс и выделенные ресурсы. Синхронизируются только объекты с метками DDP | Включено |
| «Ресурс каталога для процессов» | Если задан, процессы привязываются к этому ресурсу вместо собственного родительского. Для каноничной модели главной укажите UUID ресурса «Общие ресурсы» | — |
