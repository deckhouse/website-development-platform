Элемент «Решение» приостанавливает выполнение своей ветки до ответа пользователя. Он подходит для согласования спецификации или выбора дальнейших действий. В отличие от подтверждения запуска действия, решение сохраняет выбранный вариант и комментарий в [хранилище процесса](store/).

## Настройка элемента

Добавьте «Решение» на схему процесса и заполните его конфигурацию:

| Поле | Значение |
| --- | --- |
| «Вопрос» | Обязательный Go-шаблон текста, который увидит пользователь |
| «Адресат» | Go-шаблон, возвращающий email или UUID пользователя; несколько значений разделяются запятыми. Пустое поле означает инициатора запуска |
| «Варианты» | От двух до пяти ответов. У каждого должны быть уникальный непустой «Ключ» и «Название» для пользователя |
| «Ключ store» | Обязательный путь в хранилище без ведущей точки, например `approval` |

У элемента должна быть ровно одна исходящая связь. Для ветвления разместите после него [эксклюзивный шлюз](overview/#эксклюзивный-шлюз).

## Результат

Если «Ключ store» равен `approval`, после ответа доступны значения:

| Выражение | Содержимое |
| --- | --- |
| `{{ .store.approval.option }}` | Ключ выбранного ответа |
| `{{ .store.approval.comment }}` | Комментарий пользователя |
| `{{ .store.approval.decidedBy }}` | Email ответившего пользователя |
| `{{ .store.approval.decidedAt }}` | Время принятия решения |

Например, создайте ответы с ключами `approve` и `revise`. В условии шлюза сравните `{{ .store.approval.option }}` со строкой `approve`: положительная ветка продолжит выполнение, другая направит процесс на доработку.

## Работа с решениями

Адресаты отвечают в запуске процесса или в разделе [«Главная» → «AI-инструменты» → «Решения»](../../user/home/decisions/). Если адресатов несколько, достаточно ответа одного. Ответ принимается только один раз.

Право управлять процессом не заменяет участие в решении. Ответить может адресат или суперадминистратор; если все адресаты удалены, остаётся только суперадминистратор. При остановке процесса ожидающие решения отменяются.
