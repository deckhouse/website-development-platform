RegisterExternalService — регистрирует в портале [внешний сервис](../../external-services/) по URL и HTTP-заголовкам.

Учётные данные действие не принимает: после регистрации их добавляет администратор в настройках внешнего сервиса.

### Пример запроса

```yaml
slug: discount-limit-api
name: Сервис расчёта предельной скидки
description: Возвращает допустимый предел скидки по клиенту и товару
url: https://discount-limit.example.com
headers: {}
```

### Спецификация запроса

| Название | Обязательность | Описание |
| --- | --- | --- |
| slug | Да | Идентификатор внешнего сервиса: от 3 до 64 символов, строчные латинские буквы, цифры и дефис, не начинается с дефиса |
| name | Да | Название внешнего сервиса |
| description | Нет | Описание внешнего сервиса |
| icon | Нет | Иконка внешнего сервиса |
| url | Да | URL внешнего сервиса со схемой `http` или `https` и хостом |
| headers | Нет | HTTP-заголовки в формате `название: значение`. Название заголовка не может быть пустым |

### Ответ

Ответ действия содержит поля:

- `external_service_uuid` — UUID внешнего сервиса;
- `external_service_slug` — идентификатор внешнего сервиса;
- `external_service_name` — название внешнего сервиса;
- `url` — URL внешнего сервиса.

### Примечание

Владельцем внешнего сервиса и системным пользователем сервиса становится инициатор запуска. Проверка TLS-сертификата сервиса всегда включена.
