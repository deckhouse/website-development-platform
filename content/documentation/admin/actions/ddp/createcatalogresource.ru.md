CreateCatalogResource — создаёт ресурс каталога портала с параметрами и привязывает к нему существующие действия.

Ресурс и все его параметры создаются за один запуск. Если какой-либо параметр не проходит проверку, ресурс не создаётся.

### Пример запроса

```yaml
slug: discount-requests
name: Заявки на скидку
description: Заявки продавцов на согласование скидки
properties:
  - slug: customer
    name: Клиент
    type: String
    editable: true
    required: true
    showInSimplifiedForm: true
  - slug: status
    name: Статус
    type: Enum
    editable: true
    spec:
      default: draft
      items:
        - key: draft
          value: Черновик
        - key: approved
          value: Одобрено
bind_actions:
  - notify-approver
```

### Спецификация запроса

| Название | Обязательность | Описание |
| --- | --- | --- |
| slug | Да | Идентификатор ресурса: от 3 до 64 символов, строчные латинские буквы, цифры и дефис. Ресурса с таким идентификатором не должно быть в каталоге |
| name | Да | Название ресурса |
| description | Нет | Описание ресурса |
| icon | Нет | Иконка ресурса |
| properties | Нет | Список параметров ресурса |
| properties.slug | Да | Идентификатор параметра: латинские буквы, цифры и подчёркивание, не начинается с цифры. Идентификаторы параметров не повторяются |
| properties.name | Да | Название параметра |
| properties.description | Нет | Описание параметра |
| properties.type | Да | Тип параметра: `String`, `Number`, `Boolean`, `Date`, `URL`, `Markdown`, `Percentage`, `Enum`, `List`, `Array`, `Object`, `JSON`, `YAML`, `Entities`, `Users` или `Teams` |
| properties.editable | Да | Можно ли изменять значение параметра в форме сущности. Задаётся явно |
| properties.required | Нет | Обязательный параметр |
| properties.hidden | Нет | Скрытый параметр |
| properties.showInSimplifiedForm | Нет | Показывать параметр в упрощённой форме |
| properties.icon | Нет | Иконка параметра |
| properties.spec | Нет | Спецификация параметра. Для типов `Enum` и `List` обязателен непустой список `spec.items`: у элементов `Enum` задаётся `key`, у элементов `List` — `value` |
| bind_actions | Нет | Идентификаторы существующих действий, которые станут доступны для сущностей ресурса |

Списки `properties` и `bind_actions` можно передать как YAML-список или как JSON-строку со списком. JSON-строка получается, например, когда значение передано через параметр процесса типа JSON.

Типы параметров описаны в разделе [«Параметры»](../../../user/properties/).

### Привязка действий

Чтобы привязать действие, у инициатора запуска должно быть разрешение `update:actions` или `update:action` на это действие; супер-администратору разрешение не требуется.

Действие не привязывается, если его правила обновления записывают значение в параметр, которого нет в создаваемом ресурсе, или записывают в параметр типа `Enum` значение, которого нет среди ключей вариантов.

Если ресурс создан, а привязка действий завершилась ошибкой, ресурс остаётся в каталоге, а текст ошибки перечисляет уже привязанные действия.

### Ответ

Ответ действия содержит поля:

- `resource_uuid` — UUID созданного ресурса;
- `resource_slug` — идентификатор ресурса;
- `resource_name` — название ресурса;
- `bound_actions` — идентификаторы привязанных действий.

### Примечание

Владельцем ресурса становится инициатор запуска, командой-владельцем — команда, выбранная при запуске, а если она не выбрана, — команда-владелец сущности.
Ресурс добавляется в конец списка ресурсов верхнего уровня каталога.
