{{< alert level="info" >}}
Для выполнения действия требуется токен пользователя, от имени которого оно будет выполнено.
{{< /alert >}}

UpgradeRepositoryFromTemplatePack — переносит в репозиторий изменения новой версии [пакета шаблонов](../../../templates/).

Действие не пишет в основную ветку: оно создаёт отдельную ветку с изменениями, чтобы их можно было проверить в merge request. Какие именно файлы затрагиваются, определяет стратегия обновления.

### Пример запроса

```yaml
targetRepositoryUrl: https://gitlab.example.com/group/service.git
targetBranch: main
sourceBranch: ddp/template-upgrade-1.3.0
templateId: go-service
templateVersion: 1.3.0
upgradeStrategy: selective
updateOverwrite:
  - .gitlab-ci.yml
updateAddIfMissing:
  - docs/CONTRIBUTING.md
commitMessage: Upgrade template to 1.3.0
```

### Спецификация запроса

| Название                 | Обязательность | Описание                                                                       |
| ------------------------ | -------------- | -------------------------------------------------------------------------------- |
| targetRepositoryUrl      | Да             | HTTPS-адрес репозитория сервиса                                                 |
| targetBranch             | Нет            | Ветка, от которой создаётся ветка обновления                                    |
| sourceBranch             | Да             | Ветка, в которую записываются изменения обновления                              |
| templateId               | Да             | Идентификатор шаблона                                                           |
| templateVersion          | Да             | Версия шаблона, до которой выполняется обновление                               |
| templatePackSource       | Нет            | Название реестра, если один шаблон публикуется в нескольких                     |
| upgradeStrategy          | Нет            | Стратегия обновления; по умолчанию берётся из пакета                            |
| updateOverwrite          | Нет            | Пути, которые перезаписываются                                                  |
| updateAddIfMissing       | Нет            | Пути, которые добавляются, только если отсутствуют                              |
| values                   | Нет            | Значения шаблона                                                                |
| additionalIgnorePatterns | Нет            | Дополнительные пути, исключаемые из шаблонизации                                |
| commitMessage            | Нет            | Сообщение коммита                                                               |

### Примечание

Стратегии обновления и их поведение описаны в разделе [«Обновление сервиса»](../../../templates/#обновление-сервиса).

Обновление атомарно: если при слиянии возник конфликт хотя бы в одном файле, действие завершается ошибкой со списком конфликтующих файлов, а репозиторий остаётся нетронутым. Обновление никогда не удаляет файлы, которых нет в новой версии шаблона.
