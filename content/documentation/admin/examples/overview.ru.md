Раздел содержит пошаговые примеры настройки Deckhouse Development Portal (DDP) для типовых задач администратора.
Каждый пример описывает сценарий целиком: от подготовки до проверки результата.

## Настройка главной страницы

Примеры показывают, как подготовить главную страницу к работе с каталогом и процессами:

| Пример | Содержание |
| --- | --- |
| [Быстрая настройка главной страницы](home-quick-start/) | Мастер первоначальной настройки, учётные данные, реестр шаблонов и привязка процессов на новой установке |
| [Главная страница для собственной модели каталога](home-custom-catalog/) | Сопоставление существующих ресурсов, связей и параметров ролям главной страницы без набора данных «Каноничная архитектура» |
| [Собственный процесс заказа ресурса](home-custom-process/) | Процессы заказа и удаления общего ресурса, параметры из контекста запуска и категории слотов |
| [Виджет на вкладке микросервиса](home-widget-slot/) | Вывод виджета GitLab на вкладках карточки микросервиса через слоты виджетов |

| [Выпуск новой версии шаблона](template-release-update/) | Выпуск новой версии, ручное и автоматическое обновление микросервисов и разбор конфликтов |

## Автоматизация на основе действий и процессов

Пример [«Автоматическое обновление сервисов»](service-autoupdates/) показывает, как без шаблонов микросервисов настроить ресурсы, источник данных, действия, процесс и автоматизацию.
В результате при выпуске новой версии шаблонного репозитория в сервисах создаются запросы на слияние (Merge Request).
