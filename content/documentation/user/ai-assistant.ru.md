AI-ассистент — чат, встроенный в Deckhouse Development Portal (DDP, портал). Он отвечает на вопросы о портале, анализирует данные каталога и выполняет задачи с помощью инструментов MCP (Model Context Protocol).

На вопросы в AI-ассистенте отвечает [AI-агент](../admin/ai-agents/overview/). По умолчанию выбран платформенный агент, который разворачивается вместе с порталом.
Агент обращается к языковой модели через AI-провайдера пользователя.

Для работы с AI-ассистентом требуется глобальное разрешение `run:ai-agents`.

## Подключение AI-провайдера

AI-провайдер — подключение к языковой модели. Провайдер нужен для работы с платформенным агентом и с внешними агентами, которым разрешён прокси моделей DDP.

Провайдеры пользователя настраиваются в разделе «Профиль» → вкладка «AI-провайдеры». Провайдер можно подключить из шаблона, подготовленного администратором, или задать свою конфигурацию.

Если администратор выдал доступ к [шаблону AI-провайдера](../admin/ai-agents/provider-templates/) с общим токеном, провайдер из этого шаблона уже отображается в списке с отметками «из шаблона» и «общий токен».
Такой провайдер не подключается вручную и не удаляется.

### Подключение из шаблона

Чтобы подключить провайдера из шаблона:

1. Откройте «Профиль» → вкладка «AI-провайдеры».
1. Нажмите «Из шаблона».
1. Выберите шаблон провайдера.
1. Укажите название провайдера и выберите модель.
1. В поле «Токен» введите свой токен для API провайдера.
1. Нажмите «Сохранить».

URL, метод и заголовки подставляются из шаблона. В провайдере из шаблона изменяются только название, модель и токен; чтобы сохранить текущий токен при редактировании, оставьте поле «Токен» пустым.

### Своя конфигурация

Чтобы подключить провайдера со своей конфигурацией:

1. Откройте «Профиль» → вкладка «AI-провайдеры».
1. Нажмите «Своя конфигурация».
1. Заполните поля провайдера, как описано в разделе [«Параметры провайдера»](#параметры-провайдера).
1. Нажмите «Сохранить».

### Параметры провайдера

Своя конфигурация провайдера задаётся полями:

| Поле | Обязательность | Описание |
| --- | --- | --- |
| «Название» | Да | Название провайдера. По названию провайдер выбирается в чате и в элементе процесса «AI-агент» |
| «Модель» | Да | Название модели, например `gpt-4o` |
| «URL» | Да | URL API провайдера, например `https://api.openai.com/v1/chat/completions` |
| «Метод» | Да | HTTP-метод запроса, обычно `POST` |
| «Заголовки» | Нет | HTTP-заголовки запроса. Токен подставляется вместо `{{ .token }}` |
| «Токен» | Нет | Токен API провайдера. Хранится в зашифрованном виде и после сохранения не отображается |
| «Поле ответа» | Нет | Путь к тексту ответа модели в JSON-ответе провайдера, например `choices.0.message.content` |
| «Шаблон тела запроса» | Нет | JSON-шаблон тела запроса с переменными `{{.prompt}}` и `{{.model}}` |

URL провайдера проверяется при сохранении. URL должен:

- использовать протокол `https`;
- не содержать имени пользователя и пароля;
- не указывать на loopback-адрес, адрес частной сети, link-local- или multicast-адрес.

Агенты обращаются к модели в формате OpenAI Chat Completions, поэтому для работы с агентами укажите API, совместимый с OpenAI: URL оканчивается на `/v1` или `/v1/chat/completions`.
Поля «Поле ответа» и «Шаблон тела запроса» используются только при сжатии длинной истории чата в резюме (подробнее — в разделе [«Передача контекста»](#передача-контекста)).

### Токен в заголовках

Токен провайдера подставляется в заголовки вместо выражения `{{ .token }}`:

```text
Authorization: Bearer {{ .token }}
```

Если в заголовках нет выражения `{{ .token }}`, агенты передают токен модели как API-ключ.

### Пример провайдера для OpenAI

Пример конфигурации провайдера для API OpenAI:

| Поле | Значение |
| --- | --- |
| «Название» | `ChatGPT` |
| «Модель» | `gpt-4o` |
| «URL» | `https://api.openai.com/v1/chat/completions` |
| «Метод» | `POST` |
| «Заголовки» | `Authorization: Bearer {{ .token }}` |
| «Токен» | API-ключ OpenAI |
| «Поле ответа» | `choices.0.message.content` |

## Работа с AI-ассистентом

Окно «AI-ассистент» открывается кнопкой с подсказкой «AI-ассистент» в правой части верхней панели портала. Окно перемещается за заголовок и меняет размер за края и углы; положение и размер окна сохраняются в браузере.

При закрытии окна диалог сохраняется: повторное открытие продолжает тот же чат.

### Выбор агента и провайдера

В поле «Агент» вверху окна выбирается агент, который отвечает на вопросы. В списке отображаются платформенный агент и внешние агенты с отметкой «Внешний», доступные пользователю.
Если выбранный агент выключен, удалён или недоступен пользователю, рядом с ним отображается отметка «недоступен».

Поле «Провайдер» отображается, если модель агенту предоставляет портал: для платформенного агента и для внешних агентов с разрешённым прокси моделей DDP.
Для провайдера из шаблона со списком доступных моделей рядом отображается поле выбора модели.

### Чаты

Диалог ведётся в чатах. Слева — список чатов, сгруппированный по датам «Сегодня», «Вчера» и «Ранее», и кнопка «Новый чат».

Чаты имеют следующие настройки:

1. До 20 чатов на пользователя. При достижении лимита удалите старые чаты через меню «Действия с чатом».
1. До первого сообщения у чата служебное название. После первого вопроса название подставляется по тексту (можно «Переименовать»).
1. Удаление чата вместе с историей сообщений в нём необратимо.

Если агент не смог ответить, под сообщением отображается «Агент не смог ответить» и кнопки «Повторить» и «Подробности».

### Передача контекста

Переключатель «Передавать контекст» задаётся для каждого чата отдельно:

1. «Включено» — в запрос уходит контекст переписки в этой теме.
1. «Выключено» — только текущее сообщение. Расход токенов ниже, без «памяти» в чате.

При включённом контексте и длинной истории старые реплики не отправляются целиком каждый раз: недавние сообщения идут полностью, более ранняя часть сжимается в резюме отдельным запросом к тому же провайдеру.
Для этого запроса используются поля провайдера «Шаблон тела запроса» и «Поле ответа».

{{< alert level="warning" >}}
Включение передачи контекста увеличивает расход токенов при взаимодействии с моделью.
{{< /alert >}}

### Инструменты MCP

Агент вызывает инструменты портала, чтобы получить данные или выполнить действие. Набор инструментов агента задаёт администратор в поле «MCP-инструменты» подключения агента.
Платформенному агенту в AI-ассистенте также доступны пользовательские инструменты из [MCP-коллекций](../mcp-management/#mcp-коллекции), к которым у пользователя есть доступ.

Кнопка «Инструменты» в окне ассистента открывает список инструментов с типом (`internal`, `external`, `custom`), числом аргументов и примером запроса. Кнопка «В поле ввода» вставляет пример в поле ввода.

Вызовы инструментов отображаются в ответе агента со статусом «Вызывается», «Вызван», «Ошибка» или «Отменён», длительностью, аргументами и текстом ошибки.

- Встроенные инструменты (`internal`) и их параметры описаны в [документации MCP-сервера](../mcp-server/).
- Подключение MCP-серверов, пользовательских MCP-инструментов и настройка коллекций — в разделе [«Управление MCP»](../mcp-management/).

## Устранение неполадок

Типовые ошибки AI-ассистента:

| Сообщение | Причина и решение |
| --- | --- |
| «Для вашей учётной записи не настроен AI-провайдер. Добавьте его в настройках профиля.» | У пользователя нет AI-провайдера. Подключите провайдера, как описано в разделе [«Подключение AI-провайдера»](#подключение-ai-провайдера) |
| «Выберите AI-провайдера» | Для выбранного агента нужен провайдер. Выберите провайдера в поле «Провайдер» |
| «Недостаточно прав для запуска этого AI-агента» | У пользователя нет разрешения `run:ai-agents` или выбран внешний агент, владельцем которого пользователь не является |
| «LLM-провайдер отклонил запрос. Проверьте API-ключи в настройках профиля.» | Провайдер не принял токен. Проверьте токен и заголовки провайдера |
| «Превышен лимит запросов к LLM-провайдеру. Попробуйте позже.» | Провайдер ограничил число запросов |

Ошибки вызова внешних агентов описаны в разделе [«Внешние агенты»](../admin/ai-agents/external-agents/#устранение-неполадок).
