Обозреватель каталога — набор [MCP-инструментов](mcp-server/) для вопросов о сущностях, связях и запусках процессов. Он использует данные каталога портала и не обращается к внешним системам для их обновления. Все инструменты обозревателя только читают данные; проверка готовности также не запускает процесс.

## Настройка доступа

Для использования в AI-ассистенте настройте коллекцию и агента:

1. Создайте включённую [MCP-коллекцию](mcp-management/#mcp-коллекции).
1. В составе коллекции нажмите «Добавить в коллекцию» и выберите «Группы портала целиком» → «Обозреватель каталога». Для ограниченного набора выберите отдельные инструменты из таблицы ниже.
1. Предоставьте пользователям право использовать коллекцию.
1. На вкладке «Инструменты и навыки» выбранного агента подключите эту коллекцию.
1. Предоставьте пользователям права на нужные ресурсы, сущности, процессы и действия. Доступ к коллекции не заменяет эти права.

Для внешнего MCP-клиента привязка к агенту не требуется. Рабочее пространство использует коллекции и права владельца.

Обозреватель возвращает только доступные пользователю данные. Если видна хотя бы одна сущность, он также показывает схему её ресурса, чтобы можно было построить запрос по свойствам. Обход связей не проходит через недоступные сущности. Счётчики отражают видимую пользователю часть каталога.

## Вопросы в AI-ассистенте

После настройки [откройте AI-ассистента](ai-assistant/#работа-с-ai-ассистентом) и выберите агента с коллекцией. Например, отправьте вопрос:

```text
Какие сервисы принадлежат моим командам? Сгруппируй их по языку разработки
и покажи количество в каждой группе. Используй свойства из схемы каталога.
```

Для анализа связей укажите исходную сущность и направление интересующей зависимости:

```text
Покажи родителей сущности payments на три уровня вверх.
Для каждой сущности укажи путь связи и состояние проверок.
```

Для диагностики процессов задайте период и ожидаемую детализацию:

```text
Найди неуспешные запуски процессов за вчера для сущностей моих команд.
Покажи шаг и причину ошибки каждого запуска.
```

Если название неоднозначно, уточните ресурс или UUID сущности. Ответ зависит от заполненности каталога и записанных событий процесса. Обозреватель не делает вывод о зависании только по длительности запуска.

## Состав инструментов

В каталоге коллекций и внешнем MCP-клиенте используются следующие имена. Для модели платформенного агента и OpenCode к ним добавляется `ddp_`, например `ddp_query_catalog`:

| Инструмент | Назначение |
| --- | --- |
| `describe_me` | Текущий пользователь, команды, роли, разрешения, время и часовой пояс |
| `get_catalog_schema` | Видимые ресурсы, свойства и типы связей; с `resource` — подробности одного ресурса |
| `search_catalog` | Поиск ресурсов, команд и сущностей по словам |
| `query_catalog` | Фильтрация, подсчёт и группировка сущностей |
| `get_entity_summary` | Карточка сущности со свойствами, проверками, связями и последними запусками |
| `get_entity_relation_graph` | Обход связей с глубиной и путём от исходной сущности |
| `list_process_runs` | Поиск, подсчёт и группировка запусков процессов |
| `get_process_run` | Диагностика запуска по событиям текущей попытки: ошибки, подтверждения, повторы и таймеры |
| `find_operations` | Процессы и действия, доступные для чтения и привязанные к ресурсу сущности |
| `check_process_readiness` | Проверка параметров и условий запуска процесса без выполнения |

Описание и точные аргументы доступны в «AI» → «MCP» → «Каталог» и в `inputSchema` ответа `tools/list`.

## Примеры вызовов MCP

Следующие примеры показывают объект `params` для `tools/call`. При передаче тела запроса API используйте аргумент `body`. Сначала вызовите `get_catalog_schema`, чтобы узнать существующие идентификаторы ресурсов, свойств и связей. Идентификаторы `services` и `language` в примере замените на значения своей установки.

### Сущности моих команд

Запрос группирует сервисы команд текущего пользователя по языку разработки:

```json
{
  "name": "query_catalog",
  "arguments": {
    "body": {
      "resource": "services",
      "where": {"field": "team", "op": "in", "value": {"context": "myTeams"}},
      "groupBy": "properties.language"
    }
  }
}
```

`{"context":"myTeams"}` подставляет команды вызывающего пользователя. Для фильтра по владельцу используется `{"context":"me"}`. `countOnly: true` возвращает количество сущностей без списка; `groupBy` возвращает группы с их счётчиками. В сгруппированном ответе `total` — число групп, `entities` — число найденных сущностей.

Для выборки нескольких условий объедините их в `where.and` или `where.or`. Доступны сравнения `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in`, `contains`, `containsAny`, `isEmpty`, `isNotEmpty` и `between`; набор зависит от типа поля. Обращение к `properties.<идентификатор>` требует параметра `resource`.

### Неуспешные запуски за вчера

Запрос выбирает запуски со статусом `Failed` за предыдущий календарный день в часовом поясе Москвы:

```json
{
  "name": "list_process_runs",
  "arguments": {
    "body": {
      "status": ["Failed"],
      "team": {"context": "myTeams"},
      "since": {"calendar": "day", "offset": -1},
      "timezone": "Europe/Moscow",
      "limit": 20
    }
  }
}
```

Для скользящего периода используйте `since: {"last":"24h"}`. `countOnly: true` возвращает количество запусков; `groupBy` группирует их по `status`, `process`, `initiator`, `entity` или `day`. Эти два режима не совмещаются. Для диагностики передайте UUID найденного запуска в `get_process_run` как `run_uuid`.

В чате портал передаёт часовой пояс браузера. Внешний MCP-клиент задаёт `timezone` явно; без него используется UTC. Неизвестный часовой пояс отклоняет запрос.

### Проверка перед запуском процесса

Перед выполнением используйте последовательность:

1. Найдите сущность через `search_catalog` и получите доступные операции через `find_operations`.
1. Передайте UUID ресурса, сущности и процесса в `check_process_readiness`. В `body` укажите значения запуска: `selectedProperties`, `actions`, `context`, `skippedElementUuids` и `agentProviderRefs`, когда они нужны.
1. Проверьте `ready`, `blockers` и `approvalRequired`. Проверка возвращает первое препятствие; исправьте его по подсказке и повторите вызов. Значения по умолчанию здесь не подставляются.
1. Для выполнения отдельно вызовите операцию API `run_process` либо специализированный `curated_run_process` с его собственной схемой аргументов.

Проверка требует `control:processes` глобально, на ресурс или сущность. Читаемая операция не обязательно доступна для запуска. Между проверкой и запуском состояние может измениться, поэтому итоговый результат проверяется по ответу запуска.

## Ограничения и неполные ответы

При работе со списками учитывайте размер ответа и ограничения запроса:

- `limit` по умолчанию равен `20`, максимум — `500`. Если `hasMore: true`, продолжайте с `offset`, увеличенным на `returned`. При ограничении размера ответа строк может быть меньше, чем запрошено.
- Для графа связей `depth` задаётся от `1` до `5`. При `truncated: true` следуйте `hints`: уточните тип связи, глубину или лимит. Граф не поддерживает `offset`.
- Дерево `where` допускает до четырёх уровней вложенности и 20 условий. Если запрос слишком сложен, сузьте выборку или глубину обхода связей.
- Карточка `get_entity_summary` сокращает длинные описания и значения. Для полного поля используйте `query_catalog` с `fields` и фильтром по UUID.
- Диагностика запуска отмечает недостающие факты в `unknown`. Отсутствующее время следующего повтора или событие шага нельзя считать подтверждением ошибки.

При отказе инструмент возвращает `isError: true` с причиной и подсказкой. Исправьте указанный аргумент, уточните неоднозначную ссылку или уменьшите запрос.
