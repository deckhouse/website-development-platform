## Несовместимые изменения

### Главная страница

Прежняя главная страница — страница дашбордов, на которой администратор размещал виджеты, — удалена. Раздел «Главная» теперь занимает новая витрина каталога, и разместить на нём произвольные дашборды нельзя.

Что это значит на практике:

- Дашборды и виджеты, настроенные для страницы «Главная», больше не отображаются. Перенесите нужные виджеты на дашборды разделов «Каталог» или «Самообслуживание».
- После обновления раздел «Главная» **выключен**: пока он не включён, обращение к нему перенаправляет пользователя в «Каталог».
- Чтобы включить новую главную страницу, задайте [правила маппинга](../../admin/home/mapping-sets/) и включите раздел переключателем видимости. Быстрее всего это делается [мастером первоначальной настройки](../../admin/home/setup/).

## Новые возможности

### Главная страница

- Добавлена главная страница — витрина каталога с разделами по системам, микросервисам, окружениям, командам и ресурсам. Подробнее — в разделе [«Главная страница»](../../admin/home/overview/).
- Добавлены наборы правил маппинга, связывающие роли главной страницы с ресурсами, связями, свойствами и процессами каталога. Подробнее — в разделе [«Правила маппинга»](../../admin/home/mapping-sets/).
- Добавлены слоты виджетов: во вкладках карточки микросервиса отображаются виджеты, выбранные в правилах маппинга. Подробнее — в разделе [«Правила маппинга»](../../admin/home/mapping-sets/).
- Добавлена правка домена окружения из карточки на главной странице. Подробнее — в разделе [«Главная страница»](../../admin/home/overview/#правка-домена-окружения).
- Запущенные с главной страницы процессы отображаются на месте: строка помечается как выполняющаяся, а создаваемый объект показывается предварительной строкой до появления в каталоге. Подробнее — в разделе [«Действия из разделов»](../../admin/home/overview/#действия-из-разделов).

### Шаблоны микросервисов

- Добавлен реестр шаблонов: подключение OCI-реестра, периодическая синхронизация версий и управление их жизненным циклом. Подробнее — в разделе [«Шаблоны»](../../admin/templates/).
- Добавлено создание микросервиса из шаблона с репозиторием и файлом `.ddp/template.lock.yaml`. Подробнее — в разделе [«Создание микросервиса из шаблона»](../../admin/templates/#создание-микросервиса-из-шаблона).
- Добавлено обновление сервиса до новой версии шаблона отдельной веткой и merge request, с пятью стратегиями обновления и опциональной автоматизацией. Подробнее — в разделе [«Обновление сервиса»](../../admin/templates/#обновление-сервиса).
- Добавлена утилита `ddp-template` для проверки, локального рендеринга и публикации пакетов шаблонов. Подробнее — в разделе [«Авторам шаблонов»](../../admin/templates/#авторам-шаблонов).

### Наборы данных

- Добавлен мастер первоначальной настройки: применяет несколько наборов данных послойно и в правильном порядке. Подробнее — в разделе [«Первоначальная настройка»](../../admin/home/setup/).
- Добавлен баннер первоначальной настройки на главной странице с переключателем видимости в разделе «Наборы данных». Подробнее — в разделе [«Первоначальная настройка»](../../admin/home/setup/#запуск).
- Добавлены [наборы данных](../../admin/datasets/) для заказа managed-сервисов Deckhouse (PostgreSQL, Valkey, Kafka) и Yandex Cloud (PostgreSQL, MySQL, Valkey, Kafka).
- Добавлены [наборы данных](../../admin/datasets/) для жизненного цикла окружений, подключения общих ресурсов и схемы каталога главной страницы.

### Действия

- Добавлен механизм автоматического [удаления сущностей](../../admin/actions/overview/#удаление-сущностей) после успешного выполнения действия.
- Добавлен механизм автоматического [удаления связей сущности](../../admin/actions/overview/#удаление-связей-сущности) после успешного выполнения действия.
- Добавлена синхронизация выбранных источников данных сразу после успешного выполнения действия. Подробнее — в разделе [«Синхронизация источников данных»](../../admin/actions/overview/#синхронизация-источников-данных).
- Добавлен параметр «Владелец — инициатор»: владельцем созданной действием сущности становится пользователь, запустивший действие. Подробнее — в разделе [«Создание сущностей»](../../admin/actions/overview/#создание-сущностей).
- Добавлено действие [CreateGitlabMergeRequestReview](../../admin/actions/gitlab/creategitlabmergerequestreview/) — создание merge request для уже существующей ветки с защитой от дубликатов.
- Добавлено действие [GetGitlabPipeline](../../admin/actions/gitlab/getgitlabpipeline/) — получение состояния пайплайна.
- Добавлены действия [CreateRepositoryFromTemplatePack](../../admin/actions/gitlab/createrepositoryfromtemplatepack/) и [UpgradeRepositoryFromTemplatePack](../../admin/actions/gitlab/upgraderepositoryfromtemplatepack/).
- В действии [DeleteKubernetesResource](../../admin/actions/kubernetes/deletekubernetesresource/) добавлен параметр `ignore_not_found`: удаление уже отсутствующего объекта считается успешным.

### Процессы

Добавлен контекст запуска процесса — набор значений, которые страница или карточка передаёт процессу при запуске. Подробнее — в разделе [«Контекст запуска»](../../admin/processes/overview/#контекст-запуска).

### Свойства

Добавлен параметр [«Показывать в упрощённой форме»](../../user/properties/): если он включён, параметр отображается в упрощённой форме запуска процесса, а остальные параметры сохраняют значения по умолчанию и всё равно передаются при запуске.

### Источники данных

Добавлен источник данных [GitlabRepositoryActivity](../../admin/datasources/types/#gitlabrepositoryactivity): счётчики merge requests, последние коммиты и статусы пайплайнов проектов группы.

### Виджеты

- Расширен виджет [«GitLab. Запросы на слияние»](../../admin/widgets/gitlab/merge-requests/): счётчики по состояниям, создание merge request и построчный просмотр изменений.
- Расширен виджет [«GitLab. Пайплайны»](../../admin/widgets/gitlab/pipelines/): стадии, журналы задач, запуск, повтор и отмена пайплайнов и задач.
