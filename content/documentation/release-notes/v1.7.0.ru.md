## Несовместимые изменения

### Главная

Страница «Главная» с прикреплёнными дашбордами заменена [новой главной](../../user/home/overview/). Дашборды, прикреплённые к главной, больше не отображаются; сами дашборды и их виджеты сохраняются.
Новая главная выключена после обновления, и до её включения вкладка «Главная» скрыта у всех пользователей.

## Новые возможности

### Главная

- Добавлена новая [главная страница](../../user/home/overview/) — рабочее пространство разработчиков: команды, системы и интеграции, микросервисы, окружения, схема развёртывания систем, заказ ресурсов и потребление ресурсов кластера.
- Добавлены [правила маппинга главной](../../admin/home/mapping/), которые связывают разделы главной с ресурсами, связями, параметрами, процессами и виджетами каталога.
- Добавлен [мастер первоначальной настройки](../../admin/home/setup/), который применяет наборы данных «Каноничная архитектура»: модель каталога, правила маппинга, подключения к Kubernetes, Vault и GitLab, процессы и виджеты главной.

### Шаблоны микросервисов

- Добавлен [реестр шаблонов](../../admin/templates/registry/): портал синхронизирует пакеты шаблонов из хранилищ образов контейнеров и показывает их в галерее создания микросервиса.
- Добавлено [обновление микросервисов из шаблона](../../admin/templates/updates/): при выходе новой версии шаблона портал открывает merge request с изменениями в репозитории микросервиса — по кнопке или автоматически.
- Добавлена утилита `ddp-template` для проверки, локальной отрисовки и публикации [пакетов шаблонов](../../admin/templates/packs/#утилита-ddp-template).

### Процессы

- Добавлен [контекст запуска процесса](../../admin/processes/overview/#контекст-запуска) — корень шаблонизации `.context` с данными объектов, выбранных при запуске процесса с главной.
- Окно запуска процесса открывается в [упрощённом режиме](../../admin/processes/overview/#параметры-запуска): отображаются только важные параметры, остальные передаются со значениями по умолчанию. Полный режим открывается кнопкой «Все параметры процесса».
- Добавлен признак параметра процесса [«Показывать в упрощённой форме»](../../user/properties/#конфигурация).
- Пока выполняются процессы пользователя, значок панели «Мои активности» заменяется индикатором, а на вкладке «Процессы» отображается число выполняющихся процессов.

### Каталог

Добавлена история изменений свойств сущностей и просмотр «Свойства на момент времени». По умолчанию история хранится не менее 180 дней, срок настраивается. Подробнее — в разделе [«История свойств»](../../user/catalog/#история-свойств).

### Установка

Добавлена поддержка ClickHouse: он развёртывается в составе модуля или подключается как внешний инстанс и хранит большие объёмы данных, например историю изменений свойств сущностей. Подробнее — в разделе [«ClickHouse»](../../admin/install/#clickhouse).

### Действия

- Добавлен механизм автоматического [удаления сущностей](../../admin/actions/overview/#удаление-сущностей) после успешного выполнения действия.
- Добавлен механизм автоматического [удаления связей сущности](../../admin/actions/overview/#удаление-связей-сущности) после успешного выполнения действия.
- Добавлена [синхронизация источников данных](../../admin/actions/overview/#синхронизация-источников-данных) после успешного выполнения действия: объект, созданный или удалённый действием, появляется в каталоге без ожидания синхронизации по расписанию.
- Добавлен параметр [«Владелец — инициатор запуска»](../../admin/actions/overview/#создание-сущностей): владельцем сущностей, созданных действием, становится пользователь, запустивший действие.
- Добавлены действия [GetGitlabPipeline](../../admin/actions/gitlab/getgitlabpipeline/) и [CreateGitlabMergeRequestReview](../../admin/actions/gitlab/creategitlabmergerequestreview/) — получение состояния пайплайна и создание merge request из существующей ветки.
- Добавлены действия [CreateRepositoryFromTemplatePack](../../admin/actions/gitlab/createrepositoryfromtemplatepack/) и [UpgradeRepositoryFromTemplatePack](../../admin/actions/gitlab/upgraderepositoryfromtemplatepack/) — создание и обновление репозитория из пакета шаблона.

### Источники данных

Добавлен источник данных [GitlabRepositoryActivity](../../admin/datasources/types/#gitlabrepositoryactivity): число открытых merge request, последний коммит и последний пайплайн проектов GitLab.

### Виджеты

- Добавлен виджет [«История параметров»](../../admin/widgets/entities/property-history/), который строит график изменений параметров сущности за выбранный период.
- В виджет [«GitLab. Запросы слияния»](../../admin/widgets/gitlab/merge-requests/) добавлены фильтры по состоянию с числом MR, фильтр по целевой ветке, создание MR, сведения о MR в раскрытой строке и причины, по которым MR нельзя слить.
- В виджете [«GitLab. Пайплайны»](../../admin/widgets/gitlab/pipelines/) этапы и задачи пайплайна отображаются в раскрытой строке, а журнал задачи — в панели задачи с последними строками и полным журналом.

## Улучшения

- В действиях [DeleteKubernetesResource](../../admin/actions/kubernetes/deletekubernetesresource/) и [GetKubernetesResource](../../admin/actions/kubernetes/getkubernetesresource/) добавлен параметр `ignore_not_found`: отсутствие объекта в кластере не считается ошибкой.
- Действие [StartGitlabPipeline](../../admin/actions/gitlab/startgitlabpipeline/) возвращает объект созданного пайплайна.
- Действие [Debug](../../admin/actions/debug/debug/) принимает нулевые `sleep_time` и `sleep_count`.
- Вебхук-действие с пустым телом отправляет запрос без тела, а при ответе с кодом ошибки [сохраняет тело ответа](../../admin/actions/overview/#формат-тела-запроса) в ответе действия и в тексте ошибки.
- [AI-ассистент](../../user/ai-assistant/#работа-с-ai-ассистентом) открывается кнопкой в верхней панели в перемещаемом окне с изменяемым размером; диалог сохраняется при закрытии окна.
- Наборы данных [«Kubernetes»](../../admin/datasets/#kubernetes), «Vault» и «GitLab» требуют URL внешней системы. В наборы данных [Deckhouse managed](../../admin/datasets/#deckhouse-managed-postgresql) добавлены параметры создания ресурса, действий, процессов и источника данных.
- [Ротация ключа шифрования](../../admin/security/encryption-key-rotation/) перешифровывает пароли подключений реестра шаблонов.
- Уведомления об ошибках показывают описание ошибки, полученное от портала.

## Рекомендации по обновлению

- Перед обновлением прикрепите дашборды, которые отображались на главной, к другой странице портала кнопкой «Прикрепить дашборд», например к странице «Каталог».
- Проверьте шаблоны действий, условий и виджетов на использование функций `env`, `expandenv` и `getHostByName` и на передачу `{{ .credentials.* }}` через переменные и параметры.
- После обновления настройте новую главную по [инструкции](../../admin/examples/home-quick-start/) и включите переключатель «Показывать главную» в разделе «Администрирование» → «Справочники» → «Правила маппинга».
