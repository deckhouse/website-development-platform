## Улучшения

### Процессы

- У задачи, шага «AI-агент» и параллельного шлюза появилось поле «Таймаут (секунды)». Без значения шаг ждёт 60 минут и получает статус `Timeout`. Подробнее — в разделе [«Задача»](../admin/processes/overview/#задача).
- Схема нового процесса настраивается сразу при создании: вкладки «Конфигурация» и «Параметры» доступны до первого сохранения, процесс открывается со схемой «Начало → Конец».

## Исправления

### Процессы

- Запуск выполняется по схеме, с которой начался: правка процесса и завершение других его запусков больше не влияют на идущий запуск, его возобновление и перезапуск.
- Снята нагрузка на CPU и базу данных, пока задача процесса ждёт воркер.
- Итоговый [статус запуска](../admin/processes/overview/#статусы-процесса) определяется по обработке ошибок: обработанная шлюзом ошибка оставляет `Completed`, необработанная даёт `Partially Completed` и в процессе с одним элементом «Конец». `Partially Completed` ставится только после завершения всех веток.
- [Параллельный шлюз](../admin/processes/overview/#параллельный-шлюз), завершившийся ошибкой или по тайм-ауту, отменяет входящие ветки вместе с действиями и запусками AI-агентов; запуск не завершается, пока работает ветка, которую шлюз не дождался.
- Запуск получает `Unapproved`, только когда не осталось другой работы: шаг «AI-агент» или таймер в соседней ветке не останавливаются до согласования.
- [Эксклюзивный шлюз](../admin/processes/overview/#эксклюзивный-шлюз), у которого не выполнилось ни одно условие, не продолжает процесс по ветке с невыполненным условием, а шлюз с несколькими входящими элементами проверяет статус того элемента, после которого процесс дошёл до шлюза.
- Таймер, ожидавший во время приостановки запуска или перезапуска портала, срабатывает после возобновления. Таймер с расписанием «Определённое число каждого месяца» не пропускает месяц без такого числа.
- После перезапуска портала прерванная задача подхватывает результат уже выполненного действия, а не запускает его повторно; задача с потерянным результатом не оставляет запуск в `Running` навсегда.
- Шаг «AI-агент», который не удалось запустить, сразу получает `Failed` с причиной в логе, а не завершает процесс сообщением `process stalled`.
- Действия и запуски AI-агентов останавливаются, когда запуск завершается ошибкой, отменяется или удаляется.
- Кнопка «Возобновить процесс» и подтверждение действия больше не ждут завершения всего запуска; одновременные команды над одним запуском не теряют его прогресс.
- Управлять запуском можно только через сущность, которой он принадлежит: разрешения на одну сущность не дают управлять запусками другой.
- Таймлайн и схема завершённого запуска больше не показывают элементы выполняющимися до отметки «Сейчас».

### MCP

- Инструмент [`get_process_instance`](../user/mcp-server/#get_process_instance) возвращает хранилище процесса.
